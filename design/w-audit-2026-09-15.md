The X4 change deletes `mesh_queue.pending`, `mesh_queue.capacity`, both admission
comparisons and the post/completion counter updates. Each runtime step polls one
completion and attempts one available request, even after a zero-completion poll.
The next step proceeds immediately. A refused request leaves its cursor unchanged.
RX attempts its replacement receive before publishing the completion. Every runtime
post attempt is preceded by a CQ poll, so no whole section or ready list is issued
without intervening completion draining. The temporary completion buffer shrinks
from `2*QD` records to one per direction. No outstanding-request count replaces
the deleted counter.

`ENOMEM` and `EAGAIN` retain the unposted cursor for the next native attempt;
other post errors still reach the existing out-of-band port status. Initial
preposting fills the native queue and can reach those deferred refusals without
restarting pairing. The only
capacity comparison left checks at setup that one framed request fits the actual
QP capacity. These are source properties; hardware refusal codes and performance
have not been measured by this change. W2 and W3 remain ✗.

### X4 posting and completion bodies

```c
static int link_post(struct mesh_link *link,uint32_t q,int direction,uint32_t row,uint32_t page){
  struct hdr *m=link->M;struct mesh_verbs *v=&link->provider;
  struct mesh_queue *queue=link_queue(link,q,direction);
  struct ibv_sge span=v->device->spans[page/m->block];
  span.length=queue->bytes;
  int error;
  if(direction==MESH_SEND){
    struct ibv_send_wr request={.wr_id=row,.sg_list=&span,.num_sge=1,.opcode=IBV_WR_SEND,.send_flags=IBV_SEND_SIGNALED},*bad=NULL;
    error=ibv_post_send(v->pairs[q],&request,&bad);
  } else {
    struct ibv_recv_wr request={.wr_id=page,.sg_list=&span,.num_sge=1},*bad=NULL;
    error=ibv_post_recv(v->pairs[q],&request,&bad);
  }
  if(error && error!=ENOMEM && error!=EAGAIN)link_error(link,error,1);
  return error;
}

static int link_receive(struct mesh_link *link,uint32_t q){
  struct mesh_queue *in=link_queue(link,q,MESH_RECEIVE);
  struct mesh_receive *receive=&link->receive[q];
  if(in->next<receive->length){
    int error=link_post(link,q,MESH_RECEIVE,0,receive->first+in->next*link->M->block);
    if(error)return error;
    in->next++;
  }
  return 0;
}

static void link_send_ready(struct mesh_link *link,uint32_t q){
  struct mesh_ready *ready=&link->ready[q];
  if(ready->head<ready->tail){
    struct mesh_send_edge *source=&link->send_edges[link->send_ready[ready->head]];
    uint32_t page=atomic_load_explicit(&mesh_page(link->M)[source->row+source->offset],memory_order_acquire);
    uint32_t end=source->offset+link->M->block;
    if(link_post(link,q,MESH_SEND,end==source->pages?source->row:MESH_ABSENT,page))return;
    source->offset=end;
    if(end==source->pages)ready->head++;
  }
}

static void mesh_progress(struct mesh_link *link,uint32_t direction){
  struct hdr *m=link->M;struct mesh_verbs *v=&link->provider;
  struct ibv_wc *completions=v->completions+direction;
  for(uint32_t q=0;q<(uint32_t)link->qps;q++){
    int count=ibv_poll_cq(v->completion_queues[2*q+direction],1,completions);
    if(count<0){link_error(link,count,3);continue;}
    if(direction==MESH_RECEIVE)link_receive(link,q);
    else link_send_ready(link,q);
    for(int i=0;i<count;i++){
      struct ibv_wc *wc=&completions[i];
      if(wc->status)link_error(link,wc->status,2);
      if(direction==MESH_RECEIVE){
        if(!wc->status){
          uint32_t page=(uint32_t)wc->wr_id,source=*mesh_tag(m,page);
          struct mesh_receive *receive=&link->receive[q];
          struct mesh_target target=receive->targets[receive->next[source]++];
          mesh_receive_assign(m,target.row,page);
          if(target.publish!=MESH_ABSENT && !receive->failed)mesh_publish(m,target.publish);
        } else link->receive[q].failed=1;
      } else {
        if((uint32_t)wc->wr_id!=MESH_ABSENT)mesh_buffer_release(m,(uint32_t)wc->wr_id,1);
      }
    }
  }
}
```

### X3a receive matching prerequisite

Let independent producers A and B send equal-sized sections on one QP, with fixed
receives posted for addresses a then b. If B finishes first, sending B immediately
places B in a. Enforcing A-then-B transmission instead withholds ready B until A
finishes. The former violates X3's fixed operands; the latter violates producer
independence. Replacing the notice stack with a FIFO does not change this result:
publication order can still be B-then-A.

X3 therefore needs a realized mapping from each `(edge, instance, chunk)` to its
native channel, receive ordinal and destination page, valid for independent
producer completion orders. `mesh_transfers_prepare` currently records no such
matching plan. The plan must respect the native QP resource bound and cannot
manufacture a global send order, add a wait, copy received payload, or restore
runtime page permutation. Until row X3a exists, deleting address resolution alone
would produce incorrect operands.

## Fix order (deletions and start()-time constants only)

1. **X3a → W2 → row 19c.** Realize native receive matching for independent producers first. Then delete `mesh_receive_assign`, the in-band tag read and the `receive->next[]`/`targets[]` cursor tables; post at the plan's destination pages and publish its completion rows. Declaration-order transmission does not implement this prerequisite.
2. **W3 → row 19c.** Use the same X3a plan to replace the `send_ready` indirection and per-chunk `mesh_page[]` lookup with the planned channel and page. Preserve ready-producer independence. X4's two capacity gates and `queue->pending` counter are already deleted; the native post return is the admission decision.
3. **W6 → row 19c.** Delete `mesh_call_submit`'s remote-operand loop (:138-143) — operands are the array built once at `mesh_call_bind` (:117-125); replace Mesh.swift:288 with `Int($0.index) * stride`; replace the `MeshFeatures` dictionary (:16, :27) with a positional array indexed by a prepare-time integer.
4. **W5 → row 19e, N2.** Delete `mesh_buffer_enqueue`, `reclaim_head`, `mesh_collect`, `link_collect` and the collector thread (mesh-dataflow.c:125-130, :168-185; mesh-flow.c:221-229, :324-326, :349); at refcount → 0 in `mesh_buffer_release` push `(first,pages)` on the per-worker SPSC ring X5 names; add the one-load `Mesh.result(index)` status word.
5. **W1, W4 → row 19a.** Replace `mesh_notice_push/take/next` (mesh.h:93-112) — CAS-retry Treiber stack with `->next` walks in `mesh_call_progress` :155-163 and `link_publications` :192-202 — with start()-sized rings per (producer, consumer), so `mesh_publish` and `mesh_calls_submit` are one store each. The notice queues are multi-producer today (Metal/Core ML completion threads, RX thread, submit thread); the replacement accounts for that in its indexing, not with a guard.
6. **W2/W3 residual.** Delete the `receive[q].failed` latch (:179-180): a bad completion already records `port.code` via `link_error` (:171), the I12 out-of-band value.
