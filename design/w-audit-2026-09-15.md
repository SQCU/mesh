# W audit — withholding work, storage and execution flow

This audit follows the operator correction in [deliverables.md](deliverables.md):
I18 prohibits guards and blocks that prevent values from being drained or
transacted. Dedicated queue polling, indexed page placement, native completion
handling and the declared dependency countdown are permitted. A conditional or
page-table load is not by itself evidence of an operation wait.

The former blanket polling/indexing prohibition and its proposed immutable-address
replacement are superseded. The indexed-address correction applies to mesh `b1703a3` plus native error
normalization `7c7fee4`. `b850d53` (ABI 48) subsequently replaces publication notices as
described below. ABI 49 removes the reclamation stack and collector thread.
W1's source path is repaired; W2–W6 remain open for the reasons below. No runtime
speedup is established by either replacement.

## W1 — publish path

`mesh_call_complete` publishes output rows, releases completed input uses, then
releases each output's existing producer reference. Those references keep callback
metadata live if output readers finish before input cleanup. No extra completion
notice or reference is added.
`mesh_publish` updates presence and walks fixed numerical/link use bitmasks. Those
are indexed dataflow operations:

TX notices now precede the presence store and local consumer-mask load. The
local consumer notices follow presence. ABI 67 deletes the bitmap hierarchy.
All notification users now publish their existing index into one packed 64-bit
ring slot. Per publication the ring performs one relaxed tail fetch-add and one
release store; per consumed event it performs one acquire slot load and one
relaxed head store. An empty/unpublished head costs one acquire load and a
sequence comparison. There is no level loop, bit decoding or exchange on the
consumer path. Head and tail occupy separate aligned 128-byte regions.

Optimized ARM64 source inspection shows `ldadd` then `stlr` for each enqueue;
the dequeue reads its packed slot with `ldapr`, compares the generation and
returns the low 32-bit index directly. The generated `mesh_call_progress`
prologue reserves 160 stack bytes in this build.
This is generated-code evidence, not a measured cache-miss or latency count.
Header-derived queue address arithmetic, publication fan-out, the worker's
consumer range and its call state still precede useful work elsewhere.

A reserved but unpublished head delays later published entries in that ring.
Returning to another queue avoids a spinner waiting on that producer, but it
does not remove the dependency. This is an explicit remaining H1/H3/H4 defect;
the ring replacement cannot support a claim of immediate independent drainage.
Capacity and wrap reasoning are in the [handoff analysis](pages-and-functions.md#publication-notifications).

- ABI 50 replaced packed presence with a per-row release store. ABI 53 extended
  the stamp to identify an invocation; the current presence word is 64 bits.
- `mesh_buffer_release` publishes one free-pool bit when its decrement observes
  one. It performs no queue claim, retry, backing traversal or reader query.

Publishing a value waits for neither delivery, a consumer, nor another publisher.
Refcount zero is an ownership event, not a caller free protocol. X5/N1's instance
rings and rearming remain required independently of this repaired publish path.

## W2 — receive path

`link_progress` owns one thread per link and direction. `mesh_progress` polls one
native completion per queue and publishes it before draining returned pages and
reposting. Accumulated returns do not precede that publication. Native refusal
leaves the post cursor for the next progress pass;
there is no software outstanding-frame admission gate. A native error concludes
the affected invocation out of band. The sticky receive-failure guard is removed.

ABI 59 precompiles a 32-byte receive record per peer source-chunk index. The
completion reads its eight-byte tag and indexes that record. ABI 60 supplies the
exact logical row, buffer pointer and canonical page-entry pointer in the record;
RX stores the actual page through that pointer. Destination modulo/stride
arithmetic and the descriptor-to-page-list load are resolved at setup.
ABI 64 prepares ownership before receipt and deletes first-chunk handling.
ABI 65 retains only the final-chunk marker. Publication and storage return have
prepared completion counts: the same range-release routine processes zero, one
or several references. There is no reference-category branch in RX or TX.
Definition/binding/active-head lookups and the
per-binding stack pop are gone.

`link_receive` drains returned sections in the posting loop. For each, it walks
the K physical blocks, clears the mappings, appends the blocks to its queue's
free ring and releases only the frame references declared for that return,
then immediately attempts
posting. A native capacity refusal does not prevent consuming the next return
notice. The separate one-return-per-pass helper is deleted. No destination
availability query, credit message or runtime allocation is added to RX/TX.
The prepared row does not prove that its previous distributed lifetime has ended:
that realization requirement remains N1. Logical ordering also does not remove
X3's physical layout work. These are source facts, not a latency or complete
memory-safety claim.

The operand binding now requests contiguous placement only for declared native
view factories and Core ML predictions. Raw functions receive the canonical
mapping and perform logical scalar indexing through `mesh_operand.load` without
an auxiliary placement output. The address helper has no readiness observation,
allocation, retry or presence wait. Consumer ownership protects its page entries
through that consumer's native completion. This changes neither the unfinished
N1 receive-row bound nor X9's missing resident GPU interface.

The ABI-65 return loop iterates an immutable completion range, not a readiness
condition. Long-lived buffers have no frame reference at return; their transfer
completion already released its declared references. This removes the erroneous
second decrement of frame 0. Per-invocation receive return records the sequence
before releasing its one frame reference. Publication gains no additional notice,
wait, allocation or predicate on received data.

Row 19v replaces definition-indexed numerical dispatch with direct row-indexed
CSR ranges. The consumer record holds its function pointer, input position and
shared-input classification in one aligned 32-byte record. The separate `program`
pointer array and dispatch's input-descriptor classification read are removed.
Publication takes the stamp from the completion's existing operand/tag identity;
`mesh_publish` no longer loads the buffer's invocation to construct it.

| Address dependency | Before | After |
|---|---|---|
| Publication stamp | buffer invocation → stamp → presence | supplied stamp → presence |
| Consumer range | row → buffer definition → CSR offsets | row → CSR offsets |
| Function address | consumer function index → program entry | consumer record's function pointer |
| Input classification | function inputs → indexed section stride | consumer record's shared field |

The three row-19v dependent reads are absent from source. This is not a timing
measurement or an assertion that the complete event needs only one metadata
record: notification hierarchy, page-list and call records remain X10 work; N1
still requires complete admission/lifetime realization. Target storage is now 32(VE+S) bytes versus 8(E+S), and the
8F-byte function-pointer array is deleted (V slots, E varying/root uses, S shared
uses, F functions). Library size is unchanged at 2,612 lines, excluding the pending
control-event work. ABI 59 subsequently removes the RX row stacks and hashes.

The current dispatch memoizes the actual submit target, argument and operand
array/counts in each aligned 64-byte use record. Shared-input fan-out is expanded
at setup into the same contiguous range; arrival no longer classifies shared
inputs, follows call → function → values, or mutates a template. Initial and
recurring countdowns are computed separately before execution. The use record
addresses mutable call state directly; target selection does not read that state.

| Dispatch work | Previous source | Current source |
|---|---|---|
| Shared destinations | Find the function and traverse its call array | Already-expanded contiguous records |
| Submit target and arguments | Read the call record after the use record | Read them from the use record itself |
| Recurring shared-input count | Mutate the function template on arrival | Prepared at setup |
| Dependency state | Read/decrement the call's pending count | Same required state access |

The optimized Arm assembly loads target/context with `ldp` from the use record
and calls that target with `blr`; it does not load a function descriptor between
those instructions. This is a source/assembly dependency reduction, not a timing
claim. Notification traversal, range lookup, remote page binding and invocation
propagation remain. In particular, this does not establish one cache line for the
whole path. Use storage is 64V(E+S) bytes instead of 32(VE+S), where V is resident
frames, E varying/root bindings and S missing shared bindings. Source is
2,481 → 2,473 lines across the same eleven files; documentation is separate.
Strict C compilation, all four existing Mesh callers and the engine Mesh library
build pass. No runtime or latency result is claimed.

The earlier steps below describe how this path reached its previous form.

The subsequent H2 call binding removes `mesh_call_input` and the per-function
placement-flag array. Each aligned 32-byte use record now names its call and,
only for an unplaced remote input, its operand and first-page entry. Setup fixes
every operand's
source row, view index and page-list pointer. Local inputs and contiguous views
therefore do no arrival-time binding work. Remote inputs load their current
first page and update the address; shared inputs do this for each resident call.
`mesh_call_ready` decrements pending without reading the function, so an
incomplete varying input no longer traverses function → values → frame. The
source row also remains correct for a placed input already present at setup.
Call records change from 40-byte array elements to aligned, asserted 64-byte
records, adding 24 bytes per resident call and preventing a record from straddling
a 64/128-byte cache line. No runtime allocation, readiness query, retry, new queue
or callback is added. Source changes from 2,416 to 2,412 maintained Swift/C/header lines, excluding the separate
pending control-event work. This is a source reduction and dispatch change,
not a measured latency result. Hierarchical notices, remote page loads and
prepared launch metadata still prevent claiming complete H1/H2/H6.

The subsequent launch change stores submit, argument and operand counts inside
the existing 64-byte call record, deleting the function's duplicate submit pointer.
The worker holds its buffer base and passes its existing active-count address
directly. Launch no longer follows function → program → context, removes no
references, adds no output references, and clears no presence words. Startup
preserves the compiled ownership; the final output-return path restores it with
stores after all readers finish, before releasing the frame reference. The
[local lifetime derivation](pages-and-functions.md#output-ownership-is-prepared-before-launch)
covers zero-output calls and repeated uses. Invocation propagation and the
active-call increment remain on launch; complete H2/H5 are not claimed.
Maintained source changes from 2,455 to 2,456 lines across the same eleven files.
No shared-memory ABI change, new helper, queue, callback or runtime predicate
is added. The bind-time count bound only ensures the prepared 32-bit counts
represent the supplied operand arrays. Strict C compilation and existing caller
builds check integration, not latency or N1's cross-participant reuse proof.

The old ABI-57 lookup chain and ABI-58 compact-page-list costs above are
historical comparisons. ABI 59 removes the former chain. ABI 63 deletes the
redundant `buffer.mapping` field and `mesh_buffer_pages` accessor: the canonical
entry is directly `mesh_page(m)[row + chunk]`. It removes one dependent descriptor
load from TX, page return/reclamation and the native chunk lookup. RX completion
and indexed numerical operands already held prepared entry addresses. Buffer
metadata changes from 48 to 40 bytes; operand metadata remains 48 bytes. The
earlier 56-byte operand figure was stale; the current C layout and generated
ARM64 operand stride are 48 bytes.
Actual page loads and hierarchical notices still require multiple metadata records.
The complete X10 one-line execution requirement is not met. Multi-link striping
remains separate T3 work.

### X3a receive matching prerequisite

If receives are posted at a then b, B may arrive first at a. The page table then
names a as B's backing. A arriving at b names b as A's backing. Consumer identity
follows logical rows, not receive ordinal. Both producers may publish immediately;
there is no requirement for one native QP per independent value.

For multiple peers, source row identifiers are interpreted within each peer/link's
prepared transfer relation; equal source integers from different peers are not
the same value. Interleaving completions from the two neighbors of a ring does not
require a shared completion order. Every logical value retains its actual backing
through its own declared readers and transfers.

ABI 51 replaces the consecutive-chunk assumption. A ready send rotates after
each posted chunk. Multi-chunk contiguous inputs are placed in canonical storage
inside the consumer launch; dependencies and references remain on the received
logical rows. Metal uses a blit encoder followed by the supplied encoder in one
command buffer. CPU/Core ML placement uses the numerical worker. No layout work
runs on a TX/RX thread, no extra completion hop is inserted, and only the supplied
consumer's own inputs participate. [Storage and byte costs](pages-and-functions.md#indexed-receive-runs-and-contiguous-consumers)
are explicit; this materialization is not called zero-copy.

## W3 — send path

ABI 60 prepared the frame-reference address in its 32-byte send record and
assigned each receive frame to `buffer.binding`. The current native-request
change retains those direct lifetime bindings and deletes `link_post`.
`link_configure` prepares 64-byte aligned RECV WR/SGE records per physical pool
block and 256-byte SEND records aligned to 128 bytes per resident edge. Static
assertions verify their layouts, including the SEND common header and SGE within
the first 128 bytes. The full Apple native SEND WR alone is 128 bytes; the old
H2 promise of a complete WR plus SGE in 64 bytes was not implementable.

RX posts a prepared request by its pool index. TX selects the actual backing
address/key and posts its prepared request; no request construction or length
selection occurs in either post path. All signalled SEND completions identify
their edge. A thread-local completion countdown releases its existing buffer
and frame references once per section. This adds a counter decrement per chunk;
it adds no CQ event and never gates a post. N1's frame-lifetime proof is still
unfinished, and TX page resolution/tag writes remain H3/H6 work.

The exact-tail SEND change is removed. It could mismatch Apple's required
SEND/RECV frame counts. Setup now chooses a matched extent per queue direction,
including padding, independently of producer order. For N logical bytes and K
chunks, the posted byte total is K times that extent, not N + 8K. The
[complete accounting](pages-and-functions.md#prepared-native-requests) includes
record storage, tags and padding. Posting does not truncate a supplied request.

`link_publications` enumerates notified row bits, uses a prepared row-to-send range
and appends the ready send indices. ABI 63 immediately calls `link_send_ready`
for that selected queue. It deletes the unconditional `mesh_progress` call that
polled every queue before each newly enqueued edge reached posting. Native
capacity refusal still calls CQ progress; fatal post errors still conclude the
link. The outer TX loop continues servicing all queues. No new queue, helper,
timer, allocation or per-value readiness check is added. Together with the
mapping deletion, maintained source changes from 2,452 to 2,455 lines across
the same eleven Swift/C/header files; documentation is counted separately.
These are source-path and storage changes, not measured timing gains.
ABI 50 gives each queue a circular array sized
for its declared edges; one TX thread owns its head and tail. The [capacity proof](pages-and-functions.md#reusable-send-queue)
requires no fullness guard. `link_send_ready` resolves and posts the current chunk;
the final native completion resets its cursor before releasing the send reference.
ABI 52 carries invocation identity separately from the source row. ABI 53 recycles
receive targets and backing; forwarding therefore reuses the send edge for a new
invocation. ABI 54 adds native slot return; unbounded call/status matching and instance
admission remain N1 work.

Native queue refusal is the admission limit. Empty-queue observations do not wait
for a particular tensor. A pending request must not stop other links from draining.
ABI 51 rotates an unfinished edge to the ring tail after every accepted chunk.
Ready values share the queue without whole-section posting order. Native refusal
retains the current entry and cursor; other queues continue being polled and posted.

<a id="w4"></a>

The row-19r correction makes `link_send_ready` and `link_receive` post until their
prepared ring is empty or the provider returns a refusal. A refusal advances no
cursor, so the request remains available on the next progress pass; the enclosing
progress loop continues across other queues. TX still rotates unfinished sections
after each accepted chunk. RX preposting and runtime refill share the same loop.
The redundant setup-only receive fill loop is removed. No elapsed-time rule,
software outstanding-request threshold, remote acknowledgment or waiting retry is
introduced. This closes the one-post-per-pass delay; X10's metadata-record work is
separate and remains unfinished.

## W4 — submit path

ABI 59 computes the resident frame from the 32-bit sequence and reads that
frame's availability word. Unavailable returns busy immediately; available resets
status and publishes root notices. No submit event, hash directory, operand
allocation or wait remains. Native failure reporting retains its existing status
loads around admission. This is not yet N1's free-frame-ring admission: a selected
frame can be busy while another is free. W4 remains open. The transport does not
consult this admission word.

## W5 — result and reclamation

ABI 59's result lookup is one acquire load of `instances[index % extent].status`.
It no longer probes or validates a keyed directory. The array represents resident
frames, not retained historical labels. Final function/transfer releases directly
decrement the frame's atomic count; zero restores its recurring template and
marks it available. The numerical return path first restores its call countdown,
then releases the frame reference. Shared transfers discharge their one-time
references. The separate lifecycle thread, event rings and event arena are gone;
there is no event capacity or queue handoff between final reference and reclamation.

ABI 62 replaces the ABI-61 result code word with one atomic 16-byte snapshot,
`{value, completed}`, inside the same aligned 32-byte frame record. A link fault
preserves the completed marker, correcting ABI 61's F10 regression. A matching
completed invocation remains successful; another invocation observes the fault
or busy. RX records its invocation after publication and before producer-reference
release. No arriving-value busy store or new notification is needed.

Success makes one strong compare-exchange. Error publication alone retries if a
concurrent success changes the snapshot, retaining its completed marker; an
existing error wins. This loop updates local fault metadata and performs no
transfer retry or peer wait. Passive explicit submission now observes the program
fault; receive-driven execution still requires no submit. The Core ML chain uses
this result path within its configured window. Failure cancellation and the full
cross-participant reuse bound remain unfinished; N2 and W5 remain partial.

The optimized ARM64 result function has one `ldp` snapshot read, an acquire
`dmb ishld`, register comparisons and selection. It has no poll loop, lock call
or separate shared error lookup, and still reads its context's array address and
extent. Size and lock freedom are asserted in C. This is instruction evidence,
not a latency measurement. See [ordering and limits](pages-and-functions.md#versioned-frame-results).

ABI 49 replaces the guarded stack with an indexed section free pool. Final release
sets one bit; setup consumes free entries only when its first allocation pass has
no suitable range, then makes one further pass. No numerical or transport path
performs that allocation work. Abandoned positive counts are discharged by the
bridge at the retirement event outside active link execution, following QP
teardown. There is no collector thread or deferred-reader retry list.
ABI 53 directs received sections' final-reference events to their owning RX
thread. Posted receive-pool pages never enter the general allocator while the
link is active. Device-close retirement returns that pool, including unused rows.

The [lifetime derivation](pages-and-functions.md#reclamation-events) states the
ordinary-completion proof and failure limits. This section pool is not the X5
per-worker SPSC instance pool. The arena bound, instance admission and R2 failure cancellation still need
implementation; ABI 54 supplies native slot return. N1 cannot reuse storage
just because its submission index wraps around.

## W6 — invocation path

`mesh_call_progress` drains notices and walks prepared consumer ranges, decrementing
pending counts. Zero submits the supplied function. It never scans functions for
input presence. ABI 48 removes the notice list: `mesh_notice_take` enumerates only
pending bits using reader-local arrays, returning on an empty root.
Publication notices are now drained before output/terminal return notices, so
return cleanup and command-buffer rearming follow already queued launches.

ABI 59 eliminates invocation matching and native slot allocation. A prepared
32-byte consumer record contains its function address, input position, shared
classification and frame. The numerical worker fills that frame's operand and
decrements its pending count. Zero invokes the supplied function in the same
prepared native frame. Shared-input arrival updates all prepared frames once.
The worker restores a call's pending template when its last output reference
returns. Hash probes, backshift deletion and join/native free-index rings are gone.

Input references now end in `mesh_call_complete`, after output publication. They
no longer survive until the final reader of the call's outputs finishes. This
removes downstream work from input reclamation without moving output/native-slot
return earlier. Each output keeps its existing producer reference through that
cleanup. No additional completion event, caller release operation, allocation
or polling path is added.
See the [chain and fan-out lifetime derivation](pages-and-functions.md#input-lifetime-ends-at-its-own-use).

Indexed operands retain the canonical page list. Contiguous native inputs retain
the asynchronous placement path and its actual copy cost. Core ML and Metal view
selection remains tied to the frame. Metal's rearm callback still allocates a
new single-use command buffer; row 19s is open. The complete frame lifetime and
X10 metadata-load bound are also open; these source deletions do not close W6.

## W7 — collective compositions

All collective verbs are declarations over sends and supplied functions. Explicit
owners, destinations, routes and combine functions are realized before execution.
T2 expands a route into sends of the same received section at each relay. No route
lookup or model interpretation occurs during transport. Collective semantics do
not depend on world size or arrival order. Existing runtime defects still apply
to the realized edges.

## W8 — caller bindings

The Gram caller's supplied Accelerate operations return after producing their
outputs; their library dispatch/publication paths inherit W1–W6. This is source
composition, not evidence of distributed speedup.

Engine `769567d` and `aad2874` added copied prompt storage, host-polled stamps and
an implicit `encodeWaitForEvent(prefillDone)` in embed. `74a62ff` removes them.
The I18 clarification does not permit that wait: prefill must publish operands
consumed by decode through declared dataflow. The remaining engine attention
binding still reaches the host `attentionSplits` scan. In `lm_engine.swift:1909`,
`encodeWaitForEvent(graph.meshStepEvent, ...)` also precedes `encodeDecodeOutput`.
That implicit output-stage wait remains an E3 defect: bind output processing as a
consumer of the Mesh-produced operands instead of deleting the wait while leaving
an undeclared read. W8 is partial pending those integrations.

The concurrently integrated public report
`metal-microbench/output_data/mesh_e3/compare_A_8x8.out` reports inferior two-node
decode at engine `772a8cb` / mesh `7c7fee4`. It is the historical decode-shaped run that I21 now excludes from legitimacy
measurements. E3 acceptance requires the E5 prefill path with E4 placement; the
old run must not be repeated as validation. The launch-granularity and host-staging explanations in rows E1c/19k/19l
are implementation work to investigate and fix, not a page-table impossibility.

   retain their single-publication/declared-ownership contract during reuse.
2. X5/N1: transport and native storage return are implemented; finish instance

4. N2/E3: complete recovery and prefill-to-decode dataflow, then exercise the public
   chain using the existing measurement path. No documentation correction or
   compilation substitutes for the required speedup evidence.

The link controller retains the out-of-band pairing socket. Its existing

capacity, and the bridge restores owner after its final descriptor write. There
is no owner claim or retry in a transfer or numerical launch.

the next realization. Root and return metadata rows now carry client ownership;
retirement clears their allocation bits even though they own no payload pages.
Actual operand backing is still released only after device teardown. This repairs
the abandoned metadata-row leak without adding a runtime allocator or collector.
The library grows from 2,416 to 2,452 maintained Swift/C/header lines, including
