# H audit — dependent loads and metadata lines per hot event, `6a8d422` (MESH_VERSION 75)

Read-only recount of the four hot flows of [group H](deliverables.md#h--hot-and-cold-data-flow) at `origin/main` `6a8d422` (43 commits past `60efd51`; `rdma/` churn 948+/732−). All line numbers are that blob.

**Method.** *depth* = longest chain of loads whose address needs a prior load's value, from the event trigger to the named effect. *lines* = distinct 128 B metadata lines touched (payload excluded; ring/stream line and hdr line 0 counted once). Baseline (`f1ae04a`) and `60efd51` figures are the earlier ontology audit's; the enumeration here is explicit so the method can be checked.

## Follow-up — direct first SEND and deletion of contribution typing

The original count above remains the baseline. The subsequent source change in
`link_publications` removes the unconditional pending-range enqueue/reload before
a new publication's first native post. The TX thread holds the native-request
array base across iterations. From the event slot, the request index addresses
that array directly; queue selection no longer determines a second record lookup
before the post. Optimized ARM64 loads the prepared request header and issues
`blr` before touching the pending-range queue.

| first-post path | baseline above | changed source |
|---|---|---|
| dependency chain after reading the event | edge → queue state → pending range → edge | edge |
| TX reader through first native post, same counting convention | 6–7 dependent loads / 8 metadata lines | 3–4 dependent loads / 6 metadata lines |
| producer plus TX, including ABI 76's publication layout | 9–10 dependent loads / 13 metadata lines | 6–7 dependent loads / 11 metadata lines |

The range queue still schedules unfinished requests and native-capacity refusals;
it is not deleted globally. Its state and reload are removed from the first-post
dependency chain. Native request/provider loads, stream probing, completion
cleanup and subsequent queued posts remain. No H row passes on this evidence.
The separate TX/RX entry points also delete the worker-to-link wrapper and runtime
direction selection, with no replacement role record.

The direct path now covers every accepted request in the interval. Successful
posts advance through the prepared SEND array without pending-ring stores,
head/tail reads or range reloads. A single-request FFN publication also loses
the unconditional pending-drain call. Only native `ENOMEM`/`EAGAIN` puts an
unfinished suffix in the existing queue, immediately followed by CQ progress.
The retry drain now lives in that existing progress body; `link_send_ready` is
deleted. Optimized ARM64 keeps pending-ring addressing under the native-error
branch. This removes an intermediate record from subsequent successful posts;
it does not improve the first-post depth already reported in the table, remove
CQ polling, or establish a measured H7 pass. Wire requests, matching and storage
ownership are unchanged. [Flow and capacity argument](pages-and-functions.md#direct-tx-publication).

The Swift contribution-type feature is deleted rather than moved: no partial
flag, registry, rejection closure, privileged function binder, or completed-value
identity replacement remains. Reduction's supplied function uses public `call`.
Those are setup deletions and contribute **zero** to the runtime depth reduction
reported above. The native-call, receive-placement and ownership paths remain
subject to the original audit. No runtime workload was run.
Commit `9114872` restored the deleted L5/F1/F2 requirements. The contribution-type
deletion above is an implementation gap, not completion of those requirements.

## Follow-up — native function dispatch

Relative to `3bd1eaa`, the worker no longer traverses `MeshInvocation` or enters
its C callback adapter. Setup retains concrete Swift function values in the
existing memory owner and gives C their code/context pairs. Clang `swiftcall`
with `swift_context` supplies the native register convention. The generated
launch sequence loads `{code, context}` from the use record, loads dependency
and operand fields from the call record, then invokes the prepared code. The
Swift entry loads its actual captures directly. No generic function conversion
or block conversion lies between them.

| mechanism | before | after |
|---|---|---|
| use record | 64 bytes, including duplicate operand pointer/count | 32 bytes, asserted size/alignment |
| invocation object | one heap object read before native launch | deleted; setup ownership array has no dispatch reader |
| callback adapter | C callback unwraps object, then calls stored Swift closure | direct Swift ABI invocation |
| lifetime RMW before launch | shared `active` increment | deleted; local submitted count changes after launch returns |
| arrival admission | second `running` acquire/branch | deleted |
| native completion accounting | shared decrement after publication/cleanup | one shared completion increment in the same position |

The already-required call record supplies its operand pointer/count; removing
the copies does not introduce another record on that dependency chain. The
wrapper record and its adapter stack frame are deleted. Compiler-generated
backend closure work remains. A complete revised end-to-end depth count is not
claimed from this local deletion, and the original baseline above is retained
as historical evidence.

The engine’s decode/prefill Mesh calls now include output normalization,
projection, sampling and logprob extraction in their final command buffers.
The separate output command buffer, Mesh shared-event signal/wait pair and
serial value are removed. Host ticks observe completion without preventing
native output work from starting. Local standalone execution still owns its
ordinary synchronous command-buffer API. Session-page release follows ARC,
with failed submitted work retained by the existing graph state until teardown.
This does not implement R2 cancellation or repair the engine’s other shared
storage and contiguous-copy limitations.

The remaining H defects are still real: O(P) stream probing, receive mapping and
forwarding updates, contiguous input copies, native rearm allocation and inline
transport reference/instance bookkeeping. No H row becomes complete merely
because the dispatch subpath improved. Builds and optimized assembly are the
evidence; no runtime workload or performance result is claimed.

## Follow-up — transport retirement

Relative to `cd63fba`, native SEND completions and completed received sections
publish indices to a dedicated retirement thread. SEND's chunk countdown,
buffer reference decrement and instance release no longer execute on TX.
RX publishes the numerical value, then its logical row for retirement; it no
longer releases that section's initial reference in the completion path.
The existing references and completion counts remain unchanged on the cold
thread. See the [mechanism and capacity bound](algorithm-sources.md#transport-retirement).

The receive record replaces its now-cold completion count with the logical row
fixed at setup. Its size remains 32 bytes. Enqueueing RX retirement therefore
does not reload `publication->row`. The TX retirement-ring pointer is loaded
only on a successful native completion, after the pending-post pass; adding it
as another argument through the first-post functions is unnecessary.

Actual ARM64 assembly from the same compiler and flags (`-O2 -Wall -Wextra
-Werror`) gives this scoped comparison:

| compiled function | stack bytes before → after | completion call change |
|---|---|---|
| `mesh_send_progress` | 144 → 128 | `mesh_buffer_release` removed |
| `link_send_progress` | 128 → 128 | no extra direct-call layer |
| `link_receive_progress` | 128 → 112 | `mesh_buffer_release` removed |

`make -C rdma mesh-flow native-audit` passes. These are source/assembly results;
no workload, latency or speedup was measured. One hardware thread per link and
the index publications are added costs. RX still resets returned buffers and
accounts for their instances while reposting, and its page-table/forwarding
updates still precede publication. Stream probing and the rest of the earlier
H1–H8 defects remain. No H requirement is marked complete by this change.

### Receive return follows retirement

After `8340352`, RX also loses its receive-return reader, old-page mapping walk,
buffer reset and instance accounting. Those operations execute on the same
retirement thread; their destination is the existing pending-page array. Its
producer tail is published only after the old row/frame metadata is complete.
RX reads that tail and posts the prepared native requests; only successful
native posts advance its head. There is no fullness check or additional queue.

`link_receive` is deleted. Optimized ARM64 `link_receive_progress` keeps its
112-byte stack frame and no longer calls that function. Its remaining direct
calls are `pthread_setname_np` at entry, `mesh_publish`, and `link_error` on native
errors; posting and polling use the prepared native function pointers. The
retirement thread's stack grows from 144 to 160 bytes. TX frames and direct-call
sets are unchanged. `make -C rdma mesh-flow native-audit` passes.

The per-queue receive structure grows from 128 bytes aligned to 64 to 256 bytes
aligned to 128. Its first line contains the RX fields; the retirement-owned tail
and return reader are on the second line. This prevents producer cursor stores
from invalidating RX's cursor/geometry line. The existing page-index array and
native request allocations are unchanged. Reposting acquires the published tail;
page-table assignment, onward-SGE binding, publication traversal and their
dependent loads remain. No complete-path latency claim or H pass follows from
this source/assembly evidence, and cross-participant row reuse remains N1 work.

### Thread-local reader headers

Relative to `f1aca1d`, TX and numerical progress retain their own reader headers
at thread entry. The input-array bases/counts are immutable and the cursors have
one owner. The numerical worker also retains its target-array base. The original
input arrays remain the only reader-position storage; no replacement table,
runtime allocation, queue, callback or shared writer is introduced.

In optimized ARM64, TX's probe loop loses the link-record loads of the reader
base, count and cursor and its cursor store. The input descriptor and event slot
are still read. The first native post has the same request loads, plus one spill
of the event invocation to the local stack. The numerical worker loses its
repeated `worker->targets` reads, retaining the current use pointer across its
range walk; the retained base has a local spill/reload. These are scoped metadata
load deletions, not a claim that spills are free or every dependent load is gone.

### Publication without duplicate invocation state

ABI 79 removes `mesh_buffer.invocation` and the store to it at the end of every
CPU/RX publication. Its only runtime reader was receive retirement. Retirement
already visits the canonical page entries; it now reads `stamp - 1` before the
existing reset. The RX reference keeps the page alive through publication, and
the final-use return supplies the retirement handoff. No second identity or
replacement lifecycle record is introduced.

`mesh_publish` also takes the page entry that completion already has. RX records
hold the section's first entry and a chunk index; chunk address updates use
`entry + chunk`, while publication uses the first entry. This applies to every
transfer extent, not only one-chunk operands. Native completion uses its output
operand's existing entry pointer. The function loses the publication-row load,
page-table-base load, buffer-table-base load, and duplicate invocation store.
Optimized ARM64 writes the stamp as `add x10, x2, #24; stlr x3, [x10]`.
The RX frame grows from 112 to 128 bytes: its retained page-table base spills and
reloads after publication to form the retirement index. That cold reload is not
claimed as a deleted load. The publication range/stream loads and native call
remain; this is not a full H pass or a latency measurement.

Metal publication now binds its encoder through `MeshMetalFrame.publication`
once during frame setup. The engine stores that function in the existing layer
closure. The old `publish(output, on:)` path, per-step temporary buffer arrays,
extent calculation, frame output/target lookups and pipeline-width query are
gone. The coherent payload dispatches, barrier and signal dispatch remain, as
does command-buffer re-recording. This replaces repeated binding work; it does
not claim that encoding is free.

The engine's existing embedding gather also takes a section grid coordinate.
E2B's 35 calls become one call with grid `[rows, 35]`, preserving exactly
`output[(layer * rows + row) * width + component]` and its original table index.
This removes 34 encoder creations, binding sequences, dispatches and
`endEncoding` calls from both solo and Mesh preparation, for decode and prefill.
It introduces no new arithmetic function or model-specific transport path.
See [the gather algebra](../../../metal-microbench/docs/compute_execution.md#per-layer-inputs).

C/Swift libraries, the engine integration and the embedding Metal pipeline compile.
No GPU command was submitted by the pipeline compilation. No stage timing or
end-to-end gain is inferred from these deletions; E1d, E7 and E8 remain open.

### Delete output lifecycle work for resident working storage

The engine formerly declared all of its resident numerical working buffers as
Mesh outputs, even though no external function or transport consumed them. The
worker consequently polled and retired a return stream per intermediate and
frame, and reset each buffer after every step.

The existing setup view constructor is now public and the frame exposes its
setup index. The caller binds the same registered allocations once, then declares
only the actual function outputs. No numerical callback, queue or runtime lookup
replaces the removed output lifecycle. The model's buffer addresses are captured
by the same numerical encoders, and frame completion still bounds their reuse.

For E2B's 35 layers with per-layer input gates, non-debug outputs fall from 493
to 36. Per completed step this deletes 457 reference-release calls, 457 return
events and 457 resets. Across two frames it removes 914 return-stream bindings
and their polling entries. The remaining 36 outputs use the existing mechanism;
no per-output runtime predicate distinguishes scratch storage. The receive path,
GPU presence reads and command re-recording are unchanged. No complete H pass or
latency measurement is inferred from this source reduction.

### Delete shared consumed-peer state from the FFN sum

The supplied engine sum now holds peer descriptors across poll iterations in
lane-private shader state. It deletes the shared consumed-peer array and its
initialization/per-contribution SIMD barriers. Shape and peer count are realized
at setup, removing three encoder calls per layer. The numerical add, canonical
receive mappings, cooperative publication barrier and system visibility fences
remain. [The lane ownership argument and compilation scope](../../../metal-microbench/docs/async_collectives.md#resident-sum-state)
do not establish a latency pass or eliminate compiler spills, page-entry reads,
presence polling, publication work or command-buffer recording.

### Bind resident completion before the launch event

The native frame accessor now supplies the existing call pointer together with
its invocation address during setup. Resident frames bind their completion
handlers once, and command-buffer construction attaches them. The launch thunk
selects the prepared command and commits; it no longer constructs/registers a
completion handler between the dependency event and commit. Registration and
Swift block bridging still happen during rearm, not once for the whole program.

Resident command buffers also stop retaining each encoded resource: the realized
function and its supplied encoders already retain those resources through native
completion. The ordinary invocation path is unchanged. The prepared command table
has one reference-counted `ManagedBuffer` owner. Its fixed frame index selects a
native command reference directly. The invocation ABI now passes only the call
address: after updating the pending count, the worker issues `blr` without loading
operand fields or constructing input/output arguments. Optimized ARM64 resident
launch is `ldr w8, [x0, #24]; add; ldr; b _objc_msgSend$commit`: the existing
call's frame index and one command-reference load, no stack frame, Swift access call,
array bounds/type branch or temporary command retain/release. Pointer access stays
within the standard library's scoped API. The two inline C field accessors emit
no native calls. The frame-index load moved from C into this thunk; two unused
operand field reads and output-address arithmetic disappeared from the resident
path. The remaining descriptor depth did not change. C worker loads before this thunk and
native submission after it are outside that count. Native replay is still absent.
