# Page maps: choosers know pages, effectors know pointers (2026-11-02)

This note records a rule, the defect that exposed it, and the joint change it requires. The inventories that list
every violation are in design/data/ (permissions-compiler, permissions-frontend, send-receive-wrappings, all
2026-11-02). Where they are not yet written, this note names what they must cover.

## The rule

The operator, 2026-11-02:

- "choosers don't know about pointers, only about pages; effectors know about pointers and pages but never make any
  decisions ever. this system of constraint is both performant and memory safe *for the same shared single reason*."
- "the compiler doesn't work in pointers, offsets, etc ever, because it shouldn't have access to certain abstractions
  at all."
- "for some kernels the right thing to be reading is literal pointers, but pointers that only appeared in the data
  flow through the dereferencing of page table indices to pointer literals. … the final runtime code must be as fast
  as possible, as if it was 'hand written', but our code which generates templates or data dependencies or whatever
  may not have specific apis or specific types in order to make data-related or type-related inferences or choices."
- "get rid of every single case where a scope is trying to use an abstraction they don't have 'permission' to use,
  correct them all at once so nobody tries to grow them back, and address all of the issues all of that code was
  trying to handle (also all at once) so that nobody tries to 'invent' them again."

What the terms mean here:

- A chooser decides. Placement, storage, layout, order, routing, schedules, waits, thresholds and hazards are its
  work. The compiler, the planner, page effects and the solver are choosers.
- An effector carries out a decision. It evaluates a decided page map into addresses: a kernel's loads, a bridge SGE,
  a CPU store. It holds pointers. It decides nothing.
- The one shared reason: a chooser that sees only page maps can answer every question by algebra on maps. A pointer
  makes aliasing, lifetime and hazard opaque. Then each question grows its own special case and its own run-time
  guard. An effector that decides is where waits and checks get invented.

## The defect that exposed it

The five-rank LSTM idled 77–101 ms a tick on all ranks at once (metal-microbench docs/facts.md, 2026-11-02). The
chain of causes:

- The program lands every tick's gather in place: `allgatherv_out(mine, h)` into one `h`, and the service replays a
  one-tick declaration over it. So h(t+1) lands in the same bytes as h(t).
- Placement binds that value to the same pages at every invocation. The binding interface offers only
  `ncclMeshBufferSlots`: "slot × stride bytes past buffer.offset". That is pointer arithmetic.
- The library guards the reuse by position. A group's tables reach the bridge only when the GPU runs its link
  (nccl-mesh.c `zinth`), and the native bind records the link at the occurrence's own position. So each tick's
  receives are posted after the products that read h(t).
- The peers' SENDs race those late receives. A SEND that wins waits in the hardware's credit (TN3205).

Two halves carry one misapprehension. The program assumed the library makes in-place landing safe. The library
assumed programs reuse pages, so it guards by position and spends the credit. The specification already rules both
out:

- design/eager-execution.md: "Page reuse is answered by page assignment over the declared function (Freeing 7).
  Receipts, credits, waits on `sent` … are never the answer."
- design/whole-function.md: "Distinct landing generations or an existing causal descendant proof are required; the
  recurrent gather's two-slot theorem cannot be assumed."

## The data flow, and where pointers enter choosers

1. The program defines values each tick: z, c(t+1), h(t+1). An `out=` argument and `copy_` name a new version, not an
   address.
2. Capture and functionalization keep them as values. h(t+1) is a fresh node; the state write is a final writeback.
3. Placement turns values into addresses. This is the first chooser that holds offsets: fixed bindings, `(buffer,
   offset)` pairs, `slot × stride`, cyclic `instances`.
4. Page tables and kernels. `ncclMeshPageTableCreate` and `Compose` build tables of region pages. Generated kernels
   address through `mesh_storage_N(i)` and `mesh_index<k>`, which evaluate a map at run time, divisions included.
5. The transport plan turns entries into exact region spans. `zinth` hands them to the bridge.
6. The bridge posts receives and SENDs once linked, and advances `sent` and `landed`.
7. The consumer waits on `landed`. This is the one true data edge (read after write).

The hazard is made at step 3. It is then patched at steps 5 and 6. Renaming belongs at step 3.

## The target model

- One explicit, functional representation of address maps. For each value: invocation → (virtual page → physical
  page), composed with its layout (logical index → virtual byte). Views of views are compositions.
- Operations on maps answer every chooser question:
  - aliasing and hazards: do two maps' images meet over overlapping lifetimes?
  - renaming: a value definition gets fresh virtual pages;
  - freeing: a physical page's lifetime is the union of the virtual uses the map sends there. It returns to the free
    set when the ledger's completion prefixes prove its last access retired (rdma/mesh-lease-retire.h): local reads,
    SEND reads and landings;
  - DMA spans: the image of a landing's map, the same image at both ends;
  - waits: a consumer tile's threshold is the preimage of the tile through layout, page map and DMA unit order. This
    is the mask-mod closure the operator asked for streaming partial consumption.
- Allocation bin-packs values over the region's physical pages by exact lifetimes. Adjacent invocations of a repeated
  function never overlap where both are live. Every write is then one-sided: no check, no wait, no sync. Every receive
  of an invocation can be posted at its start.
- Specialization. Every realized run's schedule exists before it runs. So the final lowering evaluates the map
  family at each invocation. It writes pointer literals, or a base and an affine offset, into the recorded commands.
  Run time reads constants. No kernel evaluates a map; no effector chooses.

## Why no rings

A ring (cyclic slots, i mod N) is one hand-picked map. It is prohibited for these reasons:

- It makes the race on purpose. The reuse distance is fixed in the address, not in the lifetime. Whether iteration
  i + N may write slot i mod N is a run-time fact. So every ring needs a run-time guard, or a causal proof that holds
  for every schedule. The in-place `h` is the ring with N = 1, and its guard was the hardware's credit.
- It is a bounded buffer with blocking writes, and collectives are cycles. Such networks can deadlock with every
  member healthy (Kahn 1974; Parks 1995, cited in design/eager-execution.md). Bounded-memory scheduling of dynamic
  dataflow is undecidable (Buck 1993).
- This codebase has paid for rings already. The stream's 4,096-entry rings deadlocked the chain service (test-ov3,
  2026-10-31; deleted, design/zorvek.md). The relay rings needed credited slots, and the 7-line's middle link stopped
  with both ends holding data (metal-microbench docs/measurement.md).
- It is pointer arithmetic, so the compiler cannot remap a slot. Consumers compute modular addresses: the floor and
  mod "addressing artifact", at run time and in isl.
- It retires in order (FIFO). Independent work queues behind the oldest slot. A free set retires out of order.
- No hardware limit calls for one. The region is the whole memory less about 10 GiB, and every engine reaches it
  through the page table.

## Why one representation, not one fix per case

Each addressing scheme in the code is one map, encoded separately in its own layer:

- in-place landings, fixed bindings, `slot × stride`, cyclic `instances`, chain.py's generations;
- row-major and units-first layouts, `TensorLayout`, `MetalTensorLayout`;
- the written inverse and preimage (`MeshIndexInverse`, `MeshIndexPreimage`), `IndexRelation.through`;
- page tables and their composition, stream-page tables;
- landing and SEND spans as raw region offsets;
- `mesh_storage_N`, `mesh_index<k>` in kernels.

Lifetimes are not uniform, so no fixed formula fits:

- the wavefront's layer-l h is read one tick later by layer l + 1;
- a forwarded piece lives until its relay SEND completes;
- descriptor tables live until the bridge's CPU leaves them;
- ranks finish at different times;
- granularities differ: 16 KiB pages, 4 KiB frames, tiles, rows.

The defects of 2026-10-31 to 11-02 were each this one defect, patched as a special case:

- floor and mod relations that made isl eliminate divisions (a map stored as a relation, not as a function in
  coordinates);
- the written inverses and preimages added one at a time;
- the layout-union stall;
- the per-element gather lowering;
- the descriptor-for-contents SIGSEGV and the reach slot −1;
- the late receives;
- the ring deadlocks.

## The page-table interface today runs the wrong way

rdma/nccl.h's page tables exist, but they are derived from pointers:

- `ncclMeshPageTableCreate(const void* local, …)` makes a table from an address.
- `ncclMeshRegionRuns(const void* local, bytes, …)` reads a range's physical runs back from an address.

So a chooser starts from a pointer and recovers pages. The rule needs the other direction, and its parts exist:

- `ncclMeshPageBacking {first, count, page}` names physical page identities. That is a chooser's object.
- `ncclMeshPageTableCompose` composes selections of pages and copies nothing. That is a map operation.
- `ncclMeshPageTableAddress` and `ncclMeshPageTableBinding` produce an address or a Metal binding. Only the final
  lowering may call them.

In the joint change a chooser allocates page identities from the region's free set, composes them per invocation,
and hands the result to the final lowering. Create-from-pointer and RegionRuns leave chooser scope.

## The joint change

Both sides of each interface change together. No side is changed, tested and then followed by the other: each half
alone is a no-op or is wrong. Program-side generations with the link still at its position leave the race. A link
placed earlier over one reused `h` either moves nowhere or lets a fast peer overwrite h(t) under a slow rank's
products.

- Choosers: placement, page effects, the planner and the native bind lose every pointer-yielding API and concrete
  byte type. They hold page maps only. The inventories list each site and the problem it handled. Each problem gets
  one map operation as its answer.
- Effectors: kernels, the bridge and the recorder evaluate specialized maps only. Every condition, bound or choice
  in them goes, or moves to a chooser as a compile-time fact.
- The link: recorded at each invocation's start. `MetalPageArrivalReaders` (written 2026-11-02, held with this
  change) stays as a detector. Under renaming no earlier command touches an arrival, so a line in its record marks a
  page-assignment defect. It never selects a later order.
- The SEND lists stop waiting on the link. `ready` and the hardware's credit already gate them.
- Interfaces in rdma/nccl.h that become incompatible: `ncclMeshBufferSlots` (`stride`, `instances`, `invocation`) and
  `ncclMeshInvocationIndex`; `ncclMeshBuffer {buffer, offset}` wherever a chooser receives it; the stream and
  binding structs that carry region offsets into choosers.
- Programs: lstm.py keeps one `h` value a tick and no hand-made generations. chain.py's two generations go. Renaming
  is the compiler's.
