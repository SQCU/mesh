# Prepared machine

## Reference baseline

The target is a measured `S >= 1.10` over fast Gemma-4-E2B B=1 decoding by overlapping useful computation across the RDMA-connected machines. The existing executor is not a preservation constraint. Source structure and compilation alone do not establish the speedup.

The unchanged `litert-lm==0.17.1` GPU benchmark measured **180.54 decode tokens/s** and **8,963.62 prefill tokens/s** on M5 Max with 1,024 prefill tokens, 256 decode tokens, 2,048 context, speculative decoding disabled, warmup and three measured iterations. The engine's `make e2b-reference` repeats that command. `output_data/e2b-reference-20260918/{benchmark.log,run.json,generation.log,generation.json}` records the benchmark and coherent generation. The package uses WebGPU over Metal. The model revision is `b3ca0d2f076785a8f4b2219ddbd2bdb99954eae1`; SHA-256 is `181938105e0eefd105961417e8da75903eacda102c4fce9ce90f50b97139a63c`.

Google's [reference results](https://developers.google.com/edge/litert-lm/overview) and [released model card](https://huggingface.co/litert-community/gemma-4-E2B-it-litert-lm) define the upstream implementation and measurement configuration. This is not a same-weight comparison with the old safetensors executor. The old local 182.378 tokens/s citation was delta-coalesced (`output_data/mesh_e3/run.sh`) and is not a baseline. The 49.146 ms resident numerical rewrite and its constructor have been deleted, including the engine target that built it. Its previous layout and instruction tables are removed with that implementation.

## Prepared operands

`H` is the client's shared-memory mapping address; `A = H + data_off` is its payload address; `P` is the system page size; `q(r,s,o)` is the physical page bound to operand `o` for rank `r` and invocation slot `s` during preparation. These integers are resolved before GPU buffer creation. Each live operand occupies its own canonical pages. Transport registration and the numerical buffer use those same pages.

M07 uses the MLX authors' [system-coherent Metal accesses and system-scope fences](https://github.com/ml-explore/mlx/blob/main/mlx/backend/metal/kernels/fence.metal). Publication is recorded at setup. M07 observation is compiled into the original numerical consumer entry point using [Dawn’s native MSL compilation boundary](https://github.com/google/dawn/blob/main/src/dawn/native/metal/ShaderModuleMTL.mm). Pipeline reflection identifies actual operand readers during preparation; each receives direct completion and cancellation bindings. Original numerical source remains unchanged after that entry prefix. The compiler descriptions and binding searches are absent from execution. An explicit stop operand supports interrupted measurements. Each rank records only its assigned FFN, publishes its contribution to every prepared consumer, and consumes remote contributions in their final canonical backing. These operations still execute as commands inside the step replay; their crossing latency and across-step residency are not established by this construction.

The [released cache-update parser](https://github.com/google-ai-edge/LiteRT/blob/v2.2.0/ml_drift_delegate/delegate/composite/add_values_to_cache_parser.cc) uses three of its seven inputs and writes native byte-format KV outputs in place. Its other inputs support the CPU decomposition and are not read by GPU execution. The original signature still supplies them during setup, using host tensor handles over canonical pages. No floating KV conversion is inserted. Runtime replay uses the native cache output bindings directly. The engine caller aliases corresponding KV input/output names from the upstream signature at setup.

The external WebGPU binding imports the actual M01 pages through Dawn's host-mapped buffer extension. Each canonical operand has one WebGPU buffer, shared by all LiteRT views. Native numerical commands use that object's Metal buffer through the pinned provider's [Buffer::GetMTLBuffer](https://dawn.googlesource.com/dawn/+/refs/heads/main/src/dawn/native/metal/BufferMTL.mm) accessor. That accessor is setup-only and is not a stable public Dawn ABI. Separate numerical buffer objects over the same pages are deleted. The reference library supplies the numerical kernels. The deleted native Metal delegate, its SDK and its queue-residency bookkeeping are not another execution path.

M06 device preparation uses the reference provider's supported subgroup-matrix feature and native adapter limits, with `disable_robustness` and `disable_polyfills_on_integer_div_and_mod` passed to Dawn before compilation. The released `ml_drift::webgpu::Environment::Initialize(InitParams const&)` requests matrix feature `0x50034` at `0xca6450`, constructs these toggles at `0xca6598` and `0xca65f4`, and queries adapter limits at `0xca66dc`; engine `output_data/e2b-metal-replay-20260918/reference-device-disassembly.txt` records those instructions. Dawn's [Metal compiler lowering](https://dawn.googlesource.com/dawn/+/refs/heads/main/src/dawn/native/metal/ShaderModuleMTL.mm) consumes the flags before generating MSL. Engine `tools/e2b_replay.m:main` constructs the device once, enables experimental API access before adapter discovery, and installs the native error callback. No capability query or compiler option exists on the crossing path; workgroup initialization is unchanged.

`tools/prepare_e2b.py` constructs M06 regions at collective publication boundaries. Each rank region contains the previous contribution's consumer work and the next assigned FFN or vocabulary producer. Original local edges remain internal to the upstream compiler; they do not acquire canonical external buffers merely because an operation has a different name. With no requested collective cuts, the original decode graph and its greedy output form one region. The manifest supplies each published operand name explicitly. M01 contains the remaining region interfaces, model inputs and KV outputs; M04/M08 keep the same 35 FFN and one vocabulary transfer identities. All composition and native binding remain setup work.

Vocabulary selection follows the MPI Forum's [MAXLOC](https://www.mpi-forum.org/docs/mpi-5.0/mpi50-report/node135.htm): largest value, with the smallest global token index on a tie. Contiguous increasing row intervals make rank order agree with index order. M16 writes a FLOAT32 value and INT32 global index directly into the final eight-byte operand. The existing reference ARG_MAX supplies the local index; native gather and scalar conversion consume its FP16 logits. Consumer comparison reads each pair through its prepared binding, choosing the lower index on equal values. The transport treats the pair as an ordinary operand. No BITCAST, concatenation, slicing or intermediate candidate array is retained.

## Native replay

`metal_recording.h` exposes a 32-byte, 32-byte-aligned `MetalReplay`. `MetalRecorder.record` accepts the upstream encoder function and records its pipelines, grids and buffer bindings into an Apple indirect command buffer. The recorder captures only preparation. Replay uses its prepared residency set and `executeCommandsInBuffer`; it does not call LiteRT or rebuild bindings. M06 barrier positions are compiled from Metal's [pipeline reflection bindings](https://developer.apple.com/documentation/metal/mtlcomputepipelinereflection/bindings) for direct operands and explicit `useResource` declarations for indirect operands. Reflection is requested at pipeline compilation; the prepared pipeline access mask selects the directly bound read/write resources during recording. The transport binds the existing canonical GPU buffer instead of making another alias. Its receive command declares completion of the external write to that buffer; its publication command declares the indirect SEND-cell write. A barrier is emitted only when the next command conflicts with accesses since the preceding barrier (RAW, WAR or WAW), following Apple's [ICB barrier contract](https://developer.apple.com/documentation/metal/mtlindirectcomputecommand/setbarrier()). The temporary access sets are destroyed before submission; no resource lookup, dependency traversal or hazard check runs during execution. The released native delegate creates its own device; the recording library uses Apple's [dyld interposition mechanism](https://github.com/apple-oss-distributions/dyld/blob/main/include/mach-o/dyld-interposing.h) to request indirect-command-compatible pipelines at creation. The reference executable is not linked to this library.

The reference provider is the same `liblitert-lm.dylib` used by the benchmark. [Dawn host-mapped buffers](https://dawn.googlesource.com/dawn/+/HEAD/docs/dawn/features/host_mapped_pointer.md) use the canonical pages; the native Metal view for transport names those same pages. Device and queue interception applies only during preparation. Dawn's first-use buffer initialization and native queue completion signals finish before recording returns. They are not replayed at decode boundaries. The prepared resource set owns the numerical bindings after the LiteRT executors are destroyed; the old native delegate's queue-residency bookkeeping is deleted.

Engine `tools/e2b_replay.m` constructs the whole native chain from `operands.json`, including both upstream embedding graphs, all 35 FFNs, attention and finishing consumers, and vocabulary projection. A partitioned manifest supplies distinct `layer_l/contribution_r` operand names; the same caller can execute all contributions locally. It destroys compiled LiteRT executors before GPU replay. The recorded kernels and their resources remain owned by `MetalReplay`. The requested decode interval is submitted once. Its native command sequence alternates the recorded numerical program with the M13 boundary copies; no host command construction, wait or operand staging occurs between steps. This remains replay of upstream kernels, not one across-step persistent numerical dispatch or a completed distributed implementation.

The manifest carries the upstream [packed-weight options](https://github.com/google-ai-edge/LiteRT-LM/blob/main/runtime/executor/llm_executor_settings_utils.cc) and [context replacement](https://github.com/google-ai-edge/LiteRT-LM/blob/main/runtime/executor/magic_number_configs_helper.cc). `--context` defaults to the reference's 2,048. The caller supplies `LiteRtMagicNumberConfigs` before model compilation, through writable private model mappings because replacement mutates shape metadata. Read-only `CreateModelFromFile` produced a protection fault in `ReplaceMagicNumberInSubgraph`; the private mapping changes metadata without rewriting model files. The causal boolean mask and runtime parameter operands follow the upstream executor utilities.

`output_data/e2b-metal-replay-20260918/replay-boolean-mask{.log,-run.json,-memory.json}` records the current complete local chain: 1,371 native commands, 3,325 resources, 22,003,712 canonical operand bytes, sixteen token-feedback steps, and clean client/bridge exits. Every step produced 262,144 finite, nonzero logits. Warm GPU execution spans 6.098–6.890 ms. This is a BOS-seeded GPU replay measurement with no prefill or RDMA, not the reference benchmark configuration or evidence of D2. Earlier runs used an incorrectly typed attention mask and are not model-performance evidence. The unchanged 180.54 tokens/s reference remains the denominator; the required distributed speedup is unestablished.
