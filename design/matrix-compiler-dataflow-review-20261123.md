# Who chooses a matrix implementation? Review of 23 November 2026

The reference operation is `C = A @ B`. For a column partition a worker reads `A` and its columns of `B`, computes those columns of `C`, and writes the assigned result extents. Input ownership specifies whether a worker already has `A` or receives it. The bridge takes destination node and page indices and owns physical routing. The [composition request](compilation-composition-change-request.md) puts numerical and communication choices in IR before final lowering. The [shard request](unequal-shards-change-request.md) supplies counts, displacements, views and cost operands.

**A:** In metal-microbench `d8061ad9`, project code converted a named PyTorch matrix multiplication to a generic multiply-and-sum region. `RecognizeDense` recovered the contraction. `TensorMatrices` called `MatrixLayout` on both inputs and the output. Its stride reader, introduced for CPU Accelerate in `9ac02964`, returned false on a paged root before composing the strides. `NativeMember` then emitted the older SIMD-group matrix kernel. Both kernels compute the product. Output equality therefore hid the lost implementation choice. The emitted source hashes identified what ran.

**B:** The matrix constructor supplies its known axes and original operand views. The target computes which implementations can consume those views and reports the selected implementation on the originating operation. The allocator supplies the physical pages. The target binds those pages through a frame mapping or a contiguous virtual view, as required by the chosen instruction. The final writer emits that instruction. Anonymous contractions may still need pattern recognition. CPU Accelerate's flat-pointer calling convention applies at the Accelerate call.

| Target construction and allocation | `metal_candidate` constructs and groups numerical operations. `allocate_metal` lowers enough of each target program to obtain its actual storage and access records, then allocates its workspaces with the schedule. A choice sealed inside that first construction cannot automatically respond to the resulting allocation. The alternatives interface must expose the target implementation wherever this tradeoff matters. |
| Page readiness and transport | The compiler binds a sender to the word its numerical writer actually updates. Metal `a6673604` also derives page writer counts from the selected threadgroups' output footprints. The executor still copies numerical extents into and out of the bridge's indexed payloads in `page_execution.cpp`. These copies and waits contribute to the time of the call. |
| Emission, installation and execution | `metal_ir_emit_selected` and the recorder emit the chosen program and bindings. The bridge moves the indexed pages. The returning node exposes the assembled tensor. The older matrix image ran on one, two, four and five nodes. On four nodes the 1024 × 32768 × 1024 case measured 15.61 TFLOP/s against 21.26 for the fastest eager node in that cohort. Passing this check establishes correctness for that case. Strong scaling, single-GPU numerical throughput and whole-DNN latency are three distinct results. |
