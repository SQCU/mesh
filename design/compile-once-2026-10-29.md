# Compiling each kernel source once, 2026-10-29

## Why

A torch-mesh preparation compiles one Metal library per kernel instance: `kernel.pipeline` hands `_stream.pipeline` the
prelude, the command's index declarations (`layout.index_source`), the whole kernel source and one instance line.
Every instance therefore recompiles its source in full. For `streamed.metal` (100 KB, 14 non-template kernels) that is
about 97 ms warm on an M5 Max laptop, more on the Mini, and dozens of instances a preparation.

- That puts one rank's first realization seconds behind its peers. It is a candidate cause of the hourly's stalls past
  the 5 s landing deadline (chain-*-w16384, fabric-dnn). Compiling in parallel (mesh 2c26ca3c) halved the wall time but
  did not clear them.
- It loads the Metal compiler service on every rank. On the Mini, whose memory outside its 16 GiB region is about 8 GiB,
  that competes with the program itself.

## Why instances cannot share a library today

Each command's index declarations are global explicit specializations, generated by metal-recording.m
(`MetalViewMappedIndexDeclaration`, `MetalViewAffineIndexDeclaration`):

    template<> inline long mesh_index<3>(long i) { ... the command's own constants ... }
    template<> constexpr long mesh_stride<3, 0>() { ... }

The kernels call `mesh_index<N>` with a non-dependent name, resolved where the template is defined. Two commands that
lay out binding 3 differently cannot both declare `mesh_index<3>` in one translation unit, so neither a namespace per
command nor an instance-line trick separates them.

## The form

The layout is made data that the compiler specializes, instead of source text:
- **Affine views** (the common case: shape, strides, offset) become Metal function constants per binding slot.
  `mesh_index<N>` is defined once in the prelude over them: `mesh_rank_N`, `mesh_shape_N_d`, `mesh_stride_N_d` and
  `mesh_offset_N`, each `[[function_constant(...)]]`.
- **One library per source.** Each source then compiles once per process: the prelude, the source and every instance
  line its preparation names. Each command's pipeline is made with
  `newFunctionWithName:constantValues:` from its own layout values. Specialization runs the backend on one function,
  not a full parse and code generation of the source.
- **Mapped views** (index tables from `maps`) keep their source declarations until their tables become constant-buffer
  operands, which they already are at run time (index_values).

`kernel.pipeline(source, name, instance, indices, prefix)` becomes `(library of source and its instances, name, layout
constants)`, a higher-order lookup of one compiled library. No kernel body changes; only the prelude's definition of
`mesh_index`/`mesh_stride` and the generator move.

## Status

- Landed: compiling in parallel (mesh 2c26ca3c); a pointless probe compile deleted (a8b6e797); the vector path chosen
  by a plain `if` (632392a8).
- Landed: the constants form. One function owns the choice, `layout.pipeline(head, bindings, tail, name, indices)`,
  for every caller that used to write declarations into its text: kernel.py's commands, argmax, matrix, structured
  and the layout copy.
  - The constants form applies where every binding is affine and the text reads no `mesh_stride<`. Its library is
    keyed by text that holds no layout, and each pipeline is specialized by `newFunctionWithName:constantValues:`.
  - Otherwise the source form applies, unchanged: mapped views' index tables, and sparse.metal's constant strides.
  - metal-recording.m: `MetalViewIndexConstantPrelude` and `MetalViewIndexConstants` share the axis collapse
    (`MetalViewAxes`) with `MetalViewIndexExpression`.
  - Bindings 0-15 with up to 8 collapsed axes have the form. Others take the source form.
- Landed: one library for a source's instances. A specialized pipeline is its text without instances plus its
  instance line. Pipelines of one text wait until a caller reads one (state_of). That compiles a single library of the
  text and every waiting instance line, and specializes each pipeline from it.
  - kernel.py's commands are read only when a function's Commands are made, so every instance of a source that a
    preparation names before then compiles once.
  - A caller that reads a pipeline at once still compiles its own: the layout copy's pipeline_facts.
  - Twelve instances of a large source took 145 ms batched against 625 ms one at a time, cold. With Metal's shader
    cache warm it was 25 ms against 31.
