# Prepared native crossings

These are the emitted instructions in `rdma/.build/mesh-flow.s`, produced by `make -C rdma native-audit` with `-O2 -Wall -Wextra -Werror`. They describe the current native transport, not the deleted Swift/generated numerical executor. They do not establish crossing latency or distributed speedup. Provider-internal instructions and native numerical shader instructions are not counted as zero.

M08 requests user-interactive QoS in `pthread_create` attributes and destroys those attributes before preparation completes. There is no policy read or call in either progress loop. One-stream TX plus ordered RX execute four event loads when setup preposts the whole submission, or five when the submission needs refills, including the RX binding preload below. SEND and RECV use one native CQ; one thread drains it and another posts SENDs, for two spinning threads per active link independent of invocation count. Both selections occur at thread entry. For multiple independent SEND streams, the loop still loads the selected record’s QP, then additionally stores the accepted successor at its prepared cursor position and loads the next stream's cursor; the number of probes is bounded by configured streams times invocation concurrency, not the 35-layer graph. No later receive can change the prepared send order. Empty polling checks the explicit shutdown word; accepted SEND and RECV events do not read it before posting or publishing.

M08's request/QP and destination/value occupy one aligned 32-byte line at +64. TX remains two load instructions at discovery depth 0: the old paired request/successor load becomes a scalar successor load plus the fixed request-field address. One loaded pointer is deleted, not one load instruction. Ordered RX is two loads without refill, three with refill, at depth 0; the mode is selected once before the loop using actual native capacity and prepared submission length. The fully preposted path removes one event load and the native repost call. The refill path removes the successor field/load value but retains one request load, so its instruction count stays three. A successful native SEND completion uses only the CQ status/opcode load and returns to polling without touching a receive binding. Multiple independent receive queues use `wr_id`: three RX loads without refill, four with refill, at depth 1. In that latter path, `ldp x1,x0,[x8,#64]` loads the prepared request and QP together before testing whether a final-window request is absent; the asserted native layout and AArch64 instruction prevent two scalar loads. No production loop reloads a spilled register. The 112-byte frame is saved at thread entry and restored at exit. Provider internals, coherence cost and full store-to-consumer latency are not established by these counts.
