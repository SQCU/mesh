The destination/value preload is deleted by M07’s native-frame order. SEND and RECV use one native CQ; one thread drains it and another posts SENDs, for two spinning threads per active link independent of invocation count. Both selections occur at thread entry. For multiple independent SEND streams, the loop still loads the selected record’s QP, then additionally stores the accepted successor at its prepared cursor position and loads the next stream's cursor; the number of probes is bounded by configured streams times invocation concurrency, not the 35-layer graph. No later receive can change the prepared send order. Empty polling checks the explicit shutdown word; accepted SEND and RECV events do not read it before posting or publishing.
