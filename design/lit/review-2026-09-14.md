# Literature review — the mesh async-collective library and its Pallas-style API

Date: 2026-09-14. Scope: the mesh (`~/dox/mesh`: `python/mesh/{__init__,nn,kernels}.py`,
`rdma/{mesh-dataflow,mesh-flow,mesh-algebra,mesh-verbs}.*`) and its callers in
metal-microbench. Method: the specification and code were read in full; every external
source below was fetched from its primary page or PDF and is quoted verbatim, or marked
"quote unavailable". Under the [provenance law](../SPECIFICATION.md#provenance-law) papers
are level-3 support; nothing here is specification.

Sections: 1 what the code requires; 2 what is already cited; 3 prior art that solves the
same problems to the same standard, keyed to the API construct it licenses; 4 the
contemporary distributed-collective implementations, at code level (MLX in depth);
5 neglected or underused work, ranked; 6 negative boundaries; 7 gaps in this review.

## 1. What the code requires, concretely

### 1.1 The public surface (`python/mesh/__init__.py`, `nn.py`)

- `Program(backend='cpu'|'metal', region=..., coreml=...)` attaches to the canonical
  shared region and creates an algebra (`__init__.py:227-245`).
- `program.tensor(shape, block_shape, dtype, transferable, contiguous)` allocates a 2-D
  grid of blocks, each block a `Ref` over a native `mesh_view` of registered pages
  (`__init__.py:91-113`). `Ref.slice/T/broadcast/present/writable/on(peer)` are views of
  the same storage (`:23-88`).
- `BlockSpec(block_shape, index_map)` resolves a grid coordinate to a region of a bound
  tensor, clipping at the boundary (`:173-196`). `ShapeDtypeStruct` declares output shape.
- `program.kernel_call(kernel, out_shape=, grid=, in_specs=, out_specs=, peer=)` returns
  a configurator; calling it allocates the outputs and binds the expression kernel to the
  grid on the participant `peer` (`:266-292`). Kernels are expressions
  (`kernels.arguments/expression/dot/indexed_add/argsort/philox4x32/program_id`), lowered
  at setup to CPU C or Metal source (`kernels.py`).
- `program.copy(source.on(sender), destination.on(receiver), queue=)` configures a
  transfer edge; block grids are cut into the common refinement and each piece becomes a
  native copy binding (`:295-338`). `program.replicate(src, peer)` is broadcast by copy
  (`:341-362`).
- `program.export(ref) -> Result{ready, array, consume}` is a reader membership on the
  view's pages (`:199-225`); `program.write(ref)` is a host writer that publishes on
  successful exit (`:368-381`); `program.constant`, `program.realize`, `program.close`.
- `nn.linear/ffn/rmsnorm/embedding/summed_embedding` compose the above: `linear` is a
  `kernel_call` over `dot(left, right, tile_k)` with an `(mr, nr)` output BlockSpec
  (`nn.py:48-60`); `ffn` is the Megatron column/row pair with an optional `exchange=`
  hook at the hidden tile (`nn.py:74-119`); reductions are addition trees of independent
  calls (`nn.py:33-44, 65-70`).

### 1.2 The native contract (`rdma/mesh-dataflow.h`, `mesh-algebra.h`, `mesh-kernel.h`)

- Rows are the unit of presence; `mesh_row_function {input, output, inputs, outputs,
  rows, indexed, routes, active}` binds row maps to a function
  (`mesh-dataflow.h:31`). `mesh_realize(functions, bindings, returns)` fixes the program
  (`:64-65`); `mesh_issue` returns the indices whose declared inputs are present
  (`:72`); `mesh_publish_partial` / `mesh_complete` publish (`:73-74`); `mesh_consume`
  and `mesh_reader_unbind` release reader ownership (`:75-76`).
- `mesh_row_binding {first, count, binding, plane, queue, receive, bytes}` is the
  transfer edge; "ledger D5: `binding` orders blocks within `queue`; both participants
  declare the same identities and queues" (`:32-33`).
- Kernels publish sections through `mesh_kernel_publication {sections, count, context,
  publish}` (`mesh-kernel.h:6-16`): in-operation publication at section granularity.
- `mesh_algebra_source(cpu_source, metal_source, inputs, output, access_axes, ...)`
  binds compiled region kernels; `mesh_algebra_copy(source, sender, destination,
  receiver, queue)`; `mesh_algebra_observe/present/export/available/consume`
  (`mesh-algebra.h:47-66`).

### 1.3 The transport (`rdma/mesh-flow.c`, `mesh-verbs.h`)

`mesh_progress` polls every completion queue with `ibv_poll_cq(..., QD, ...)`, retires
completions in posted order, treats a receive completion as presence
(`mesh_receive_complete`) and a send completion as reader release
(`mesh_send_complete`), then posts ready receives and sends (`mesh-flow.c:233-270`).
QP+1 is an index queue carrying 4096-byte descriptor frames of `mesh_transfer` tuples
(`:165-217`). There is no completion channel; the bridge is a busy-polling progress
engine, and the algebra side is fired from a `dispatch_source` on a Unix datagram
(`mesh-dataflow.c:883-884`). QPs are `IBV_QPT_UC`, `max_send_sge=1`, registrations
`IBV_ACCESS_LOCAL_WRITE` only (`mesh-verbs.h:179-195`); the in-flight window is derived
from the 4095-WR frame budget (`mesh.h:49-50`).

### 1.4 The stated contract and standards

- [async-collectives.md](../async-collectives.md): "A producer publishes a finished
  region while independent production continues. Publication does not wait for delivery,
  acknowledgement, consumption, or completion of the enclosing tensor operation. A
  consumer executes the partial numerical work whose operands exist while independent
  inputs remain absent." "Reduction contributions remain contributions until the
  configured reduction has all its required terms; nonlinear consumers read the
  resulting values, not unfinished sums." "Implement these dependencies using
  established library functions and canonical mesh mechanisms. ... Do not insert
  wrappers, parallel representations or invented algorithms around it."
- [AGENTS.md](../../AGENTS.md): "Every new function must cite an author/publication in
  design/algorithm-sources.md"; "Shared-memory operands ... must be the actual
  RDMA-sendable pages named by the canonical page table".
- [collective-dependency-ledger.md](../collective-dependency-ledger.md) D1–D16: SEND into
  a posted RECV only; two-sided made one-sided by an always-accepting receive loop;
  progress is polling a CQ; RECV posted on the consumer's pages; per-queue FIFO pairing;
  equal frame counts; producer never waits; presence = receive completion; repost after
  readers finish; collectives stream by chunk (Rabenseifner); one all-reduce per
  Megatron block; errors out of band; metadata exchanged once.
- Operator directives (memory, 2026-09-08..13): event-fired never scanned; memory
  mapping not control flow (distinct pages per live value; no guards); Amdahl
  superiority as the only legitimacy; fail-stop `Result` values, no in-band sentinels;
  static review of dataflow code, not load tests; no benchmarks on private APIs.

### 1.5 Measured facts every proposal must respect

~0.28 ms per Metal command-buffer crossing (issue→GPU ~70 µs, GPU end→handler ~60 µs,
RDMA ~18 µs); shared-event gating ~1 ms per wait; M4 Pro GPU 4.4x slower when commands
are >~200 µs apart; M4/M5 rate 0.73 at B=8, 0.12–0.15 at B≥128; decode bound ≤1.42x
(B=8) and ≤1.09x (B≥128) before any transport; prefill two-node 0.898x matched
(12B, 2048 rows); 1 GiB delivery 9.334 GB/s vs 9.383 direct verbs; per-verb costs
`ibv_post_send` 398 ns, `ibv_post_recv` 668 ns, `ibv_poll_cq` 44 ns
([transport-call-latency-2026-09-10.md](../transport-call-latency-2026-09-10.md),
[e2b decode bound memory](../../../../.claude-personal/projects/-Users-mdot-metal-microbench/memory/e2b_decode_two_node_amdahl_bound.md)).

## 3. Prior art that solves the same problems, keyed to the construct it licenses

Tag key: SOLVES = published mechanism directly usable under the rules (two-sided,
caller placement, no invented algorithm); BOUNDS = a ceiling, model or negative result;
NEGLECTED = applicable and uncited.

### 3.1 The transport: two-sided-only, credit-controlled SEND/RECV

- **Apple, TN3205.** "To check work requests for completion, poll for completion using
  `ibv_poll_cq`"; "Polls Thunderbolt send descriptors directly without making syscalls."
  https://developer.apple.com/documentation/technotes/tn3205-low-latency-communication-with-rdma-over-thunderbolt
  — ALREADY-CITED; add the poll-only sentence: there is no completion channel on this
  stack, so "no host scan loop" can only mean *one* poller that never computes.
- **hellas.ai, AD/FA57 (2026-05-28).** "Apple's `rdma_en*` exposes UC only — RC, UD, and
  READ all fail at `modify_qp` with `-ENOTSUPP`." "On Apple's UC path the CQE fires when
  the descriptor leaves the SQ ring, well before the bytes are delivered to the peer."
  "events get coalesced every 5s" when the receive path idles. Mac→Linux ~10 µs RTT at
  4 KiB, ~28 Gb/s single QP at 16 KiB.
  https://blog.hellas.ai/blog/thunderbolt-ibverbs/6-ad-fa57/ — ALREADY-CITED; add these
  three quotes (D1, D12, and the idle-coalescing hazard that licenses keeping the poller hot).
- **MLX JACCL `rdma.cpp` / `rdma.h`.** `init_attr.qp_type = IBV_QPT_UC`;
  `max_send_sge = 1`, `max_recv_sge = 1`; `MAX_SEND_WR = 32`, `MAX_RECV_WR = 32`;
  `FRAME_SIZE = 4096`; `attr.path_mtu = IBV_MTU_1024`; `src.packet_sequence_number = 7`
  hardcoded; `return ibv_poll_cq(completion_queue, num_completions, work_completions);`
  and nothing else; GID/QPN over a `TCPAllGather` side channel; registration flags
  `IBV_ACCESS_LOCAL_WRITE | IBV_ACCESS_REMOTE_READ | IBV_ACCESS_REMOTE_WRITE`.
  https://raw.githubusercontent.com/ml-explore/mlx/main/mlx/distributed/jaccl/lib/jaccl/rdma.cpp
  — ALREADY-CITED (mesh_impl.h); the QP/MR facts are the independent confirmation of
  D1/D3/D13. Note JACCL registers remote flags TN3205 says not to; unused.
- **llama.cpp PR #26421, Apple RDMA transport for `rpc` (merged 2026-08).** "a SEND and
  its corresponding RECV must cover the same number of 4 KiB Thunderbolt frames, so
  every SEND posts a whole 128KiB stride over the wire, even when partially filled."
  Lossless UC via "hardware credit based flow control". 27B: +107% prefill, +125% decode
  vs TCP; manual flush after commands +6% decode by reducing empty frames.
  https://github.com/ggml-org/llama.cpp/pull/26421 — NEGLECTED: same transport, same
  frame-quantisation constraint as D6; its measured stride cost bounds tile sizing.
- **Kalia, Kaminsky, Andersen. *Design Guidelines for High Performance RDMA Systems*,
  ATC 2016** ("design choices including which RDMA operations to use and how to use
  them significantly affect observed performance");
  ***FaSST*, OSDI 2016** ("up to 8x higher throughput, and 13.9x high CPU efficiency than
  FaRM's RPCs"); ***eRPC*, NSDI 2019** ("one CPU core can handle up to 10 million small
  RPCs per second, or send large messages at 75 Gbps"). — NEGLECTED / SOLVES: the
  two-sided-first design literature; validates SEND/RECV-only as a design, not a handicap.
- **Liu, Wu, Panda. *Flow Control Schemes in MPI over InfiniBand*, CAC 2004.** Software
  credit accounting with piggybacked credit return. Quote unavailable. — SOLVES (D2/D6).
- **Linux InfiniBand tag-matching doc.** "if there is no pre-posted receive for this
  arriving message, it is passed to the software and placed in the unexpected message
  list." https://www.kernel.org/doc/html/v5.8/infiniband/tag_matching.html — BOUNDS: TB5
  has no unexpected queue (credits refuse the send), so mesh is a pure pre-posted eager
  protocol; cite to say why there is no rendezvous path.

### 3.2 The progress engine and event firing

- **NCCL `proxy.cc`** — ALREADY-CITED (D2). **MSCCL++, ASPLOS 2026.** "each channel
  creates its own CPU thread. The CPU thread reads data transfer or synchronization
  requests from a first-in-first-out request queue"; PortChannel data path is
  "ibv_post_send for RDMA". https://arxiv.org/html/2504.09014 — NEGLECTED: the
  contemporary published shape of `mesh_progress` (one poller per port channel that
  only moves requests; never computes).
- **Treichler, Bauer, Aiken. *Realm*, PACT 2014.** "every Realm operation takes an event
  as a precondition, and the operation is guaranteed not to begin until the precondition
  event has triggered." "When invoked, every Realm operation returns immediately with an
  event that triggers when the operation completes." "events in Realm represent control
  dependences only—events carry no data and copies are themselves operations in the
  graph." https://cs.stanford.edu/~sjt/pubs/pact14.pdf — NEGLECTED, high priority: this
  is `kernel_call`/`copy` as graph operations with completion events, and Realm's
  generational events are the published answer to per-step slot reuse without claim
  checks (the guard defects deleted 2026-09-13).
- **Bauer, Treichler, Slaughter, Aiken. *Legion*, SC12.** "Legion uses a deferred
  execution model that decouples the issuing of operations from when operations are
  performed." "It is often useful to have multiple physical instances of a logical
  region (e.g., to replicate read-only data, or to allow independent reductions that are
  later combined)." https://legion.stanford.edu/pdfs/sc2012.pdf — NEGLECTED: reduction
  instances are the published form of K-partials in distinct storage; the
  `reads/writes/reduces` privilege is the type that should annotate `kernel_call`
  arguments.
- **Kalé et al. *Charm++*.** "message-driven execution, where the processor-level
  scheduler selects only those computations for which all data dependencies have been
  satisfied." https://charm.cs.illinois.edu/newPapers/13-46/paper.pdf — SOLVES.
- **von Eicken, Culler, Goldstein, Schauser. *Active Messages*, ISCA 1992.** "The PUT
  handler simply reads the address and length, copies the data and increments the
  flag." https://www.cs.utexas.edu/~dahlin/Classes/GradOS/papers/activemsg.pdf — SOLVES:
  receive completion running the dependent partial arithmetic is an active-message
  handler.
- **Schneider, Hoefler, Grant, Barrett, Brightwell. *Protocols for Fully Offloaded
  Collective Operations*, ICPP 2013 (Portals 4).** "The counters are associated with
  triggered operations (put, get, atomic, counter-increment, and counter-set) which are
  executed when the counter reaches a certain threshold." Also: "the decision if a
  message is an expected or unexpected message can not be made without host CPU
  involvement." https://htor.ethz.ch/publications/img/schneider-portalsoffload.pdf —
  NEGLECTED: threshold-fired chaining is "completion count reaches N ⇒ fire"; it also
  proves where the host must intervene (receive-state changes = D9).
- **Murray et al. *Naiad*, SOSP 2013.** "a timely dataflow system must guarantee that
  v.OnNotify(t) is invoked only after no further invocations of v.OnRecv(e,m,t'), for
  t' ≤ t, will occur." "A pointstamp p leaves the active set when its occurrence count
  drops to zero." https://sigops.org/s/conferences/sosp/2013/papers/p439-murray.pdf —
  NEGLECTED: the two-callback split between "a partial arrived" (`OnRecv`) and "no more
  partials for this key" (`OnNotify`) is exactly the firing condition for a nonlinearity
  after a K-reduction, computed by counts, never by scan.
- **Hoefler, Lumsdaine, Rehm. *LibNBC*, SC 2007**, and Open MPI `coll/libnbc/nbc.c`:
  a collective is compiled into rounds of `MPI_Isend/Irecv` separated by barriers;
  `NBC_Progress` tests pending requests and starts the next round; "check if we can
  make progress - not in the first round, this allows us to leave the initialization
  faster and to reach more overlap".
  https://raw.githubusercontent.com/open-mpi/ompi/main/ompi/mca/coll/libnbc/nbc.c —
  NEGLECTED: the only overlap literature whose transport assumptions equal TN3205's.
- **Abadi et al. *TensorFlow* whitepaper 2015.** "the Send and Receive nodes impart the
  necessary synchronization between different workers and devices, and the master only
  needs to issue a single Run request per graph execution."
  https://www.tensorflow.org/extras/tensorflow-whitepaper2015.pdf — SOLVES: cross-device
  edges rewritten to Send/Recv node pairs = `program.copy` bindings.
- **Hamidouche et al. *GPU-Initiated Networking for NCCL*, 2025** ("The Proxy backend
  provides equivalent functionality via lock-free GPU-to-CPU queues over standard RDMA
  networks") and **Shan et al. *GICC*, 2026** ("the NIC signals completion to both GPU and
  host memory, letting a lightweight host thread recycle NIC resources concurrently with
  GPU execution"). https://arxiv.org/abs/2511.15076, https://arxiv.org/abs/2604.22126 —
  NEGLECTED: Apple has no GPU-initiated NIC path; the proxy/recycle-thread designs are
  the ones that transfer.

### 3.5 Collectives as composed SEND/RECV

- **van de Geijn & Watts. *SUMMA*, CCPE 1997 (LAWN 96).** "Hence the matrix-matrix

### 3.7 The Metal crossing

- **MLX `mlx/backend/metal/distributed.cpp`.** `"[AllReduce::eval_gpu] has no GPU
  implementation."` (likewise AllGather, Send, Recv, ReduceScatter). MLX collectives
  run on the CPU stream via the CPU command encoder (`backend/cpu/distributed.cpp`:
  `distributed::detail::all_sum(group(), in, outputs[0], stream())`). — MLX pays the
  same GPU→CPU→GPU crossing per `all_sum` that the mesh measured; there is no GPU-native
  collective path in MLX either.
- **MLX `mlx/backend/metal/fence.cpp` (`MLX_METAL_FAST_SYNCH`).** On macOS 15+ the
  fence's fast path allocates a GPU buffer holding a `uint32_t` counter; CPU streams
  enqueue atomic waits/updates on it and GPU streams run `fence_wait` / `fence_update`
  kernels (preceded by an `input_coherent` kernel and `barrier()` when crossing
  devices) instead of `MTLSharedEvent` waits. — NEGLECTED, directly on point: Apple's
  own answer to the ~1 ms shared-event wait the mesh measured; WWDC26 passes
  `--env MLX_METAL_FAST_SYNCH=1` in the reference cluster config.
- **MLX `mlx/backend/metal/device.cpp`.** "Metal locks a command buffer's residency at
  commit time"; batching thresholds `max_ops_per_buffer_` / `max_mb_per_buffer_`
  (phone 20/40 MB, pro 40/40, max 50/50); MLX PR #1864 "dynamic ops per buffer". —
  cite as the published amortisation of the crossing.
- **Metal 4 (WWDC25 #205; Moore, *Getting Started with Metal 4*, 2025).** "By awaiting a
  particular value on the CPU and signaling that value from a Metal 4 command queue, we
  can safely wait for work completion without unduly wasting CPU cycles." "Command
  allocators cannot be reused while the commands they encoded are in-flight."
  https://metalbyexample.com/metal-4/ ; **Crosley 2026**: "ML inference runs on the GPU
  timeline, in the same command buffer as render and compute work. The app does not
  round-trip through the CPU." https://blakecrosley.com/blog/metal-4-essentials —
  NEGLECTED: queue-side wait/signal is the sanctioned route to event-fired dependent
  dispatch without per-step host crossings.
- **Anukari devlog (2024–25).** "MacOS won't up-clock the GPU for latency-sensitive
  audio, so Anukari now burns one warp on useless spin work. Latency dropped about 40
  percent." https://anukari.com/blog/devlog/huge-macos-performance-improvements ;
  **vllm-metal #713 (2026-09)**: "GPU clock parking plus slow ramp hysteresis: short bursts
  measure the parked-clock rate on a perfectly healthy machine"; **btop #1833**: IOReport
  DVFS states, "67% GPU activity at 338 MHz". — NEGLECTED: third-party evidence and a
  measurement method for the M4's 4.4x gap penalty and the 338 MHz polling observation;
  licenses a keep-busy strategy as established practice.

### 3.8 Performance models and the legitimacy criterion

- **Amdahl 1967; Gustafson 1988** (prefill throughput with V in flight is a Gustafson
  regime; decode is Amdahl); **Karp & Flatt 1990** — the experimentally determined
  serial fraction e = (1/ψ − 1/p)/(1 − 1/p): NEGLECTED / SOLVES — turns "Amdahl
  superiority" into a per-run measured number that separates intrinsic serial fraction
  from crossing overhead. **Hockney 1994** (t0 + n/r∞; n½ ≈ α·β ≈ 1.5–2 MB at 0.28 ms
  and 5–7 GB/s — every decode message is below it). **Culler et al. *LogP* 1993 /
  *LogGP* 1995** ("has one additional parameter, G, which captures the bandwidth obtained
  for long messages") — the o term is the dominant cost. **Valiant *BSP* 1990** — the l
  term the dataflow design deletes. Quotes for the ACM classics unavailable.
- **Pope et al. *Efficiently Scaling Transformer Inference*, MLSys 2023.** "The
  resulting communication time is Tcomm = 2BLE/network bandwidth"; "At small batch sizes
  and sequence lengths, the time to load weights dominates"; the communication latency
  "remains roughly constant independent of the number of chips used."
  https://arxiv.org/abs/2211.05102 — NEGLECTED / BOUNDS: the closed form from which the
  1.09–1.42x decode bound is derivable, adding an α per crossing.
- **Singhania et al. 2025** ("TP starts to outperform HP as workloads become more
  memory-bound and decode-heavy"; "message sizes range from 128 KB to 1 MB")
  https://arxiv.org/abs/2511.09557 — BOUNDS. **Song et al. *DSD*, 2025** ("DSD reduces
  cross-node communication cost by approximately (N-1)t1(k-1)/k") https://arxiv.org/abs/2511.11733
  — the crossing-amortisation formula for speculation with t1 = 0.28 ms.

## 4. Contemporary distributed-collective implementations, at code level

### 4.1 MLX distributed (fetched 2026-09-14)

- **Backends** (docs): MPI; Ring — "Ring all reduce and all gather over TCP sockets.
  Always available and usually faster than MPI"; JACCL — "Low latency communication with
  RDMA over thunderbolt. Necessary for things like tensor parallelism"; NCCL. `init('any')`
  order in `distributed.cpp`: nccl, ring, mpi, jaccl. Ops: `all_sum, all_max, all_min,
  all_gather, send, recv, recv_like, sum_scatter` ("Sum `x` across all processes in the
  group and shard the result along the first axis across ranks").
  https://ml-explore.github.io/mlx/build/html/usage/distributed.html
- **JACCL topology**: "there needs to be a thunderbolt cable connecting all pairs of Macs
  directly"; hostfile `rdma` lists the device per peer; "Starting from macOS 26.2, RDMA
  over thunderbolt is available"; `rdma_ctl enable` in Recovery; `all_gather_factory`
  side channel. PR #2808 (merged 2025-12-17): "latency optimized for now and only
  supports full mesh but ring and bandwidth optimization should come later"; TB5 only;
  send/recv "crashes with SIGBUS under asymmetric timing conditions".
  https://github.com/ml-explore/mlx/pull/2808
- **`mesh_impl.h`**: `MESH_MAX_PEERS = 8`, `MESH_PIPELINE = 2`, `WC_NUM = PIPELINE *
  MESH_MAX_PEERS * 2`; WR id `SEND_WR << 16 | buff << 8 | rank`; "Fully connected all
  reduce with deterministic reduction order. We copy rank 0's data to the output buffer
  and then we reduce every subsequent rank in-place in the output."; "Fully connected
  reduce scatter. The input holds size_ contiguous chunks of `count` elements each. Every
  rank keeps chunk rank_ and needs the elementwise reduction of that chunk across all
  ranks."; "per (sz, buff) tile there are size_ send slots (slot p → peer p) and size_
  recv slots (slot p ← peer p)"; `all_reduce_scatter_gather` "moves size_x less data per
  link at the cost of an extra communication phase".
- **`ring_impl.h`**: RS then AG over "wires"; "This wire owns slice lw of every region and
  only touches left_[lw] / right_[lw]"; "Restricting polling to a single wire's
  connections is what allows several wires to run concurrently"; `dispatch_wires` runs
  "the first n_wires - 1 on the pool and the last inline".
- **`rdma.cpp/.h`**: see §3.1. **`jaccl.cpp` (lib)**: `JACCL_RANK/MLX_RANK`,
  `MLX_IBV_DEVICES` ("a full connectivity matrix"), `MLX_JACCL_COORDINATOR`; chooses
  `RingGroup` if preferred and valid, else `MeshGroup`, else ring.
- **TCP ring `ring.cpp`**: `ALL_SUM_SIZE = 8 * 1024 * 1024`; `BUFFER_SIZE =
  max(32768, min(ALL_SUM_SIZE/sizeof(T), segment_size/2))`; "Two times the same send/recv
  operations, first scatter reduce and then gather."; "we keep a send and a recv in
  flight while doing the summation"; one `SocketThread` per socket; "It is required to
  have as many connections to the left as to the right"; `send/recv` neighbour-only.
- **Graph integration**: collectives are lazy primitives with `eval_cpu` only; the Metal
  `eval_gpu` throws (§3.7); `jaccl.cpp` (backend glue) dispatches
  `encoder.dispatch([...]{ group_->all_sum(in_ptr, out_ptr, n_bytes, dtype); })` on the
  CPU command encoder with raw array pointers; "[jaccl] Group split not supported".
- **Layer-level TP** (`python/mlx/nn/layers/distributed.py`): `AllToShardedLinear`
  weight `(output_dims // N, input_dims)`, `ShardedToAllLinear` weight
  `(output_dims, input_dims // N)`; `ShardedToAllLinear.__call__`: `x = x @
  self["weight"].T; x = mx.distributed.all_sum(x, group=self.group)`; docs: "All-to-sharded
  and sharded-to-all layers naturally go together because the output of the former layer
  is exactly the input needed for the latter. This removes the need for an intermediate
  gather step between the layers". `mlx-lm` `llama.py` `shard(group)`:
  `shard_linear(layer.self_attn.q_proj, 'all-to-sharded', group=group)`,
  `shard_linear(layer.self_attn.o_proj, 'sharded-to-all', group=group)`,

  `model.shard(tensor_group)` or `model.model.pipeline(pipeline_group)`.
- **WWDC26 session 233**: four M3 Ultras, mesh; "What's nice about JACCL, it
  automatically picks the best topology depending on the message size and communication
  operation — mesh when latency matters, ring when bandwidth matters."; "The cluster
  generates tokens at nearly three times the rate of a single machine for Qwen 3.6
  model." (27B, 4 nodes); pipeline "does NOT speed up inference"; standalone
  `jaccl::init()` C++ API. https://developer.apple.com/videos/play/wwdc2026/233/
- **Third-party TB5 numbers**: Geerling (via AppleInsider) Qwen3-235B 19.5 → 26.2 tok/s
  on two M3 Ultras (1.34x) → 31.9 on four; Weldon 2026: "160 communications × 300
  microseconds = ~50 milliseconds per token", TP 16 tok/s vs PP 5 tok/s for 70B FP16.
  exo README: "day-0 support for RDMA over Thunderbolt 5", TP "up to 1.8x speedup on 2
  devices and 3.2x speedup on 4 devices" (homogeneous), auto placement (forbidden here).

**MLX vs mesh, concretely.**

| | MLX JACCL | mesh |
|---|---|---|
| QP / SGE / MR | UC, sge 1, MR flags incl. remote (unused) | UC, sge 1, `LOCAL_WRITE` only |
| WR budget | `MAX_SEND_WR = MAX_RECV_WR = 32` | `QD 4095`, window = 4095/frames-per-block, re-queried via `ibv_query_qp` |
| Message | power-of-two buffers, `FRAME_SIZE 4096`, `path_mtu 1024` | block = `-B` pages (e.g. 64×16 KiB), 4096-byte index frames |
| Operand storage | its own registered `SharedBuffer`/`staging_mem_`/`scatter_buffers_`; copies in and out | the canonical pages themselves (R5, zero copy) |
| Completion | `ibv_poll_cq` inline in the collective, on the CPU stream | `ibv_poll_cq` in a separate bridge process; algebra fired by `dispatch_source` |
| Reduction | deterministic rank order, in place in the output after all receives | addition tree over distinct partial values; publish per region |
| Granularity | whole array per call; no partial publication | per block / per kernel section (`mesh_kernel_publication`) |
| Pipeline | depth 2 per peer | window-deep; receives posted up front on planned pages |
| GPU crossing | `eval_gpu` throws; CPU stream + `MLX_METAL_FAST_SYNCH` fence kernel | Metal completion handler → publish; RECV completion → commit |
| Failure | throws `std::invalid_argument`; SIGBUS reported on asymmetric send/recv | errno into `hdr.port`, never exit (D12, R11) |
| Placement | `shard_linear` strategy per layer, homogeneous ranks | caller `BlockSpec` + `.on(peer)`, heterogeneous shares |

The mesh's contract (partial publication, presence-fired consumers, never-waiting
producers, zero-copy registered operands) is strictly stronger than what MLX offers;
MLX's TP speed comes from homogeneous nodes and whole-array collectives, and it pays the
same per-layer CPU crossing.

## 5. Neglected or underused, ranked

1. **SUMMA (1997)** — `nn.linear/ffn` K-panel streaming over send/recv is a named,
   MPI-native algorithm; cite instead of describing tiles as if invented.
2. **DTensor `Partial` placement** — a type for "pending reduction"; make it the type of
   `dot` outputs so a nonlinearity cannot be bound to a `Partial` (the partial-sum rule
   becomes a binding-time check, not prose).
3. **Realm events + Legion reduction instances / `reduce` privilege** — every
   `kernel_call`/`copy` returns a completion event; generational events replace per-step
   guards; `reduces` privilege annotates partial outputs.
4. **Concurrent Collections + I-structures** — the publish/fire model in its canonical
   form for the memory side (where Monsoon/TTDA cover the token side).
5. **Synchronous Dataflow (+ CSDF)** — compile-time page-budget proof from BlockSpec
   rates; the "static streaming audit" as balance equations.
6. **Naiad OnRecv/OnNotify** — count-based "all terms present" for reduction keys; the
   firing rule for nonlinearities after a K-reduction.
7. **Korthikanti sequence-parallel + vLLM `fused_allreduce_rms_norm` contract** —
   reduce-then-norm as the sanctioned production form; the equivalence
   `norm(all_reduce(partials), residual)` as the acceptance statement.
8. **MSCCL++ PortChannel proxy / Portals 4 triggered ops / LibNBC** — published shapes
   of "one poller that only fires" and "threshold-fired chains" over two-sided transports.
9. **MLX `MLX_METAL_FAST_SYNCH` fence kernel + Metal 4 queue-side wait/signal** — the
   Apple-native route around the 1 ms shared-event wait and the 0.28 ms crossing.
10. **Karp–Flatt + Pope et al. + Hockney/LogGP** — make "Amdahl superiority" a measured
    serial fraction with a derivable bound rather than an asserted ratio.
11. **DaCe memlets / Sequoia / PTG** — `copy` edges with static subset + volume; index
    maps as affine task-instance dataflow from which sends are derived.
12. **FlashOverlap / Galaxy / TPI-LLM** — tile-completion-triggered sends over ordinary
    two-sided calls on heterogeneous devices; TPI-LLM's "link latency, not bandwidth".
13. **Anukari / vllm-metal #713 / btop #1833** — GPU clock parking as documented practice;
    keep-busy is established, not invented.
14. **llama.cpp PR #26421** — the 128 KiB stride quantisation on the identical
    transport, and a flush-to-coalesce measurement.
15. **Kalia ATC'16 / FaSST / eRPC; RCU grace period; Lamport 1977; Disruptor** — the
    two-sided-first and single-writer literature for page stamps and reposting.

## 6. Negative boundaries (cite so nobody re-attempts)

- One-sided mechanisms are unavailable on this substrate: RDMA WRITE/READ/atomics
  (TN3205; hellas `-ENOTSUPP`; "uc_write_verify confirms the receiver MR is unchanged"),
  hence NCCL LL/LL128 flags, NVSHMEM, Triton-distributed, TileLink/FLUX tile signals,
  Async-TP symmetric memory, DeepEP, T3, Iris — borrow the tile-wait *schedule*, never
  the transport. The Apple Developer Forums post recommending RDMA WRITE contradicts
  TN3205.
- Architectural fixes (Ladder-Residual, Kraken, Parallel Track, Sync-Point Drop,
  CAAT-Net, MTP heads) change the model; Gemma-4 weights are fixed.
- Auto-placement / cost models (GSPMD propagation, Alpa, Helix max-flow, Halda,
  Cyclops mapping, exo topology-aware placement) are outside the interface by contract.
- TokenWeave: below ~1024 tokens per iteration, decomposing for overlap "results in
  worse performance" — consistent with the measured decode bound; overlap is a prefill
  lever.
