## 5. Key Mechanistic Findings

1. **Zero-CPU-touch `had8g` dominates mid-to-large batches (`B=4, 8, 16, 64, 128`):** Because FWHT-64 is linear, summing quantized peer blocks in the Hadamard domain on the GPU (`fused_sum_norm_had8_bfloat`) before running a single inverse FWHT-64 eliminates bridge CPU reduction work while keeping the `1.88×` wire compression and Dreyfus–Wagner Steiner multicast dedup — pushing `B=128` from `13.86 ms → 12.39 ms` (`10,285 tok/s` agg) with **8/8 exact token parity**.
2. **Pareto auto-selection (`MESHMLX_WIRE=auto`):** Uses `gather` (`bf16` fused directly in `gemv_publish`) for `<= 2` pages (`B <= 2`, `4.44 ms` / `225 tok/s/stream`) and `had8g` for `> 2` pages (`B >= 4`).
3. **Next frontier (torch.export → single native Metal CB):** Even with `mx.async_eval`, MLX graph construction + dispatch still costs ~0.5–1.5 ms/step (`steps_ms[-1]` drain at `B=1` is `4.18 ms` = `239 tok/s` vs `4.43 ms` steady). Lowering `torch.export` FX graphs directly to a single pre-encoded native Metal CB replaying these same kernels + flat-DMA doorbells removes Python/framework overhead entirely.
