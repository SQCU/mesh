The one thing that doesn't scale

Almost every configuration step turned out to be remotely automatable. Exactly one is not, and it defines the shape of the whole rollout.

Hard gate · no remote path exists

RDMA can only be enabled from Recovery OS. Running the tool under a booted system fails outright, and no amount of privilege changes that — it is not a permissions problem, it is a refusal:

$ sudo rdma_ctl enable
rdma_ctl: This tool needs to be executed from Recovery OS.   exit=77

$ rdma_ctl status
enabled          # the bit itself lives in NVRAM and does persist

Entering 1TR requires physically holding the power button. That is a deliberate Apple anti-tampering property, so it cannot be delegated to MDM, to a script, or to a remote console. Budget exactly one physical visit per machine, forever. The entire remaining design is about making that visit the only one.

How the bootstrap paradox breaks

The obvious way to enable SSH is gated behind a permission you can only grant by hand. There is a second door.

macOS routes systemsetup through TCC, so the canonical command fails on a fresh machine even as root. But launchd has no such gate — bootstrapping the service directly needs only root:

# The documented path — blocked, and unblockable without a GUI or an MDM profile:
$ sudo systemsetup -f -setremotelogin on
setremotelogin: Turning Remote Login on or off requires Full Disk Access privileges.

# The path that works on a headless, never-touched machine:
$ sudo launchctl enable system/com.openssh.sshd
$ sudo launchctl bootstrap system /System/Library/LaunchDaemons/ssh.plist
Connection to 127.0.0.1 port 22 [tcp/ssh] succeeded!

This is what collapses the physical visit from "configure the whole machine" to "run one script." It also survives reboot on its own — launchctl enable writes through to the persistent disabled-services database, where both lifelines now read false.

Per-machine runbook

Ordered because the ordering is load-bearing — each step unlocks the next. Target: under five minutes of hands-on time.

  1. Setup Assistant

    Hands

    Create the admin account. Decline iCloud, Siri, analytics. Leave FileVault off — that choice is what makes every later reboot unattended. Confirm Activation Lock is Disabled before going further; if it is on, Recovery workflows get much worse.

  2. Recovery: enable RDMA

    Hands

    Hold the power button to reach 1TR, open Terminal, run rdma_ctl enable, reboot. This writes rdma-enable=1 to NVRAM and is the only step with no remote equivalent — do it while you are already standing there.

  3. Run the bootstrap

    HandsLast touch

    One script from USB: enable sshd via launchctl, drop the pubkey roster into authorized_keys, fetch mesh-node-setup.sh. Verify port 22 answers, then walk away. Nothing after this point requires the room.

  4. Configure over SSH

    Remote

    Run mesh-node-setup.sh: power policy, boot resilience, screen sharing, service order, watchdog and caffeinate daemons, job harness. Idempotent, so re-running it is the drift fix.

  5. Join the fabric

    Remote

    Cable it in, then discover peers with ping6 -I bridge0 ff02::1 — every neighbour answers on link-local regardless of which port the cable landed in. Confirm a device reports PORT_ACTIVE and record the node in the roster.

Why there are no static addresses

A node may be unplugged, bagged, carried to another room, and replugged into a different position in the mesh. Addressing has to survive that.

Pinning each end of a Thunderbolt link to a fixed address encodes position, not identity — two nodes that both believe they are 10.10.10.1 collide and partition the fabric the first time they meet. Identity instead travels with the machine: a stable Bonjour name, IPv4 link-local with ARP collision-probing, and an IPv6 link-local address derived from the interface MAC. All three come up automatically on whatever port the cable lands in.

$ ping6 -c3 -I bridge0 ff02::1
16 bytes from fe80::10a3:dac:d9ff:7c4d%bridge0, time=0.454 ms

$ ping -c1 Ms-MacBook-Pro.local
PING ms-macbook-pro.local (169.254.174.248)   # resolves to the FABRIC, not Wi-Fi

Bonjour independently preferred the Thunderbolt path over Wi-Fi for the peer's name — so the fast link gets used by default without any routing configuration. One rule keeps that safe: the Thunderbolt bridge stays last in service order, so a peer can never advertise itself as the default route and blackhole the node's uplink.

Open items

Jumbo frames

The link runs MTU 1500 while the RDMA device reports 4096. Raising it is a paired change — one end alone blackholes large packets, so it needs both machines in hand at once.

Uplink is Wi-Fi only

en0 has no cable. For a node that must never be unreachable, wired ethernet with a DHCP reservation should carry management traffic.

Naming scheme

Bonjour identity is per-node and must be unique. Two machines out of the box named MacBook-Pro.local will collide — decide the scheme before node three.

Pubkey roster

The list of keys each node feels fondly about should be one file, version-controlled, pushed to every node — not hand-appended per machine.

The peer is unmanaged

The MacBook answers SSH but has had none of this applied. It is currently a client of the mesh, not a node in it.

Fleet enrollment

ADE + MDM collapses steps 1 and 3 entirely. It does not collapse step 2 — the Recovery visit survives any amount of fleet tooling.
