# Mesh release closure

The release goal is to repair the seventeen defects found by the whole-repository
algorithm review without narrowing the demonstrated workload, fabric, game, or
policy scope.

Completion requires all of the following:

1. Sparse W/L transition rewards are the only policy and value training rewards.
2. Every object called a Gram matrix is exactly a Gram matrix.
3. Participant coupling and residual-scale fusion have independent interventions.
4. Live cart-game semantics agree with the formal partizan evaluator.
5. Every located strategy assignment carries its distance-derived travel horizon.
6. Push-cart and suppress-cart remain distinct through the server actuator.
7. Cart paths are synthesized inside the continuously feasible motion-plan space.
8. Participant joins and departures preserve per-participant temporal succession.
9. Policy optimization, not only inference, uses every assigned mesh host.
10. Operating-point search uses available measures without turning missing coordinates
    into pressure toward an engine ceiling.
11. Live whole-mesh aggregates contain exactly the currently reachable leased fabric.
12. V-cell execution scatter/gathers complete causally independent controller updates.
13. Belief integration and cart planning consume the same stock-navmesh Voronoi object.
14. Generic team interfaces represent all 256 teams without fixed-width team bitsets.
15. DPP computation remains on the tensor execution path and contributes to utilization.
16. Integrated policy velocity has one unambiguous cadence in persistence and action.
17. Map fusion realizes the requested stock-map and bridge support and derives join
    properties from the computed graph.

Implementation claims live in `design/claims/`. Each claimfile cites the controlling
specification, identifies the implementing data and control flow, and defines the
measurements required to substantiate the claim. Source comments and docstrings are not
claim storage and must not redefine these interfaces.

No test suite is part of this release contract. Verification consists of builds, syntax
and import checks, live measurements, mathematical invariants, telemetry support, and
rendered/runtime observations.
