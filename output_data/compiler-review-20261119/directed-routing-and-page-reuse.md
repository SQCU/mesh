## A: Where the extra constraints came from

Each cable endpoint advertised a rate. The bridge took the lesser rate and reported it in both directions. The compiler repeated that minimum, required symmetric routing operands and called its packer separately on each function's demands. R5 subsequently ordered the resulting hops across calls. It could change when the bridge sent those bytes, but the earlier packing calls had already chosen their paths. A3 assigns a rate to each direction, A4 assigns the complete transfer set to routing, and R5 prices each directed resource. The compiler passes all demands to the same Garg–Könemann packing call. A repeated body contributes its bytes times its occurrence count. Each body receives its own integral byte ranges from the solution. The bridge can select cables using the rate for the direction of that transfer. Each rank still refers to its adjacent peer in the compiled program.
