# Scalar matrix-exponential control: retained-source boundary

Observation at mesh1989a938 and nativee020d644; no implementation or target in this review.

- The primary source is JAX `jax/_src/scipy/linalg.py`, quoted in `design/torch-source-lowering-change-request.md` §6: `_calc_P_Q` selects one Padé function with `lax.switch`; `expm` selects `_nan` or `_compute` after P/Q production. The `cond`→`select` rule cited there is specifically batching over predicates, not every scalar condition.
- `operations.py:_matrix_exponential`2309–2334 emits the powers and every candidate's products before `torch.where` selects U/V. The original branch membership has therefore disappeared before `decompose._expanded` traces the formulation and before native Transform. The later `where` has already computed inputs; it does not supply a conditional operation interval.
- The same formulation solves P/Q and squares before selecting NaNs. Its existing result→Check dependency preserves error-result ordering, but does not suppress solve/squaring work on overflow. The source overflow branch covers that work, not the earlier P/Q production.
- Existing target conditional IR is local to a function: `metal_lower.h:Builder::When`94 uses Tint `b.If`, with True/False blocks and ExitIf. It cannot by itself condition an arbitrary set of separately dispatched kernels. `NativeCondition` in `metal_program.h`27 is a retained protocol warm/period mask, not a matrix-data predicate.
- The installed Metal SDK `MTL4ComputeCommandEncoder.h`127–140 exposes `executeCommandsInBuffer:indirectBuffer:`. Its existing API reads a GPU-addressed `MTLIndirectCommandBufferExecutionRange` (4-byte aligned, residency required). Current `NativeICBEncode` in `metal_program.h`275–280 instead uses the prepared span's fixed NSRange.
- A complete next handoff must retain the actual source predicate, branch operations and result/effect ownership before formulation tracing discards them, and pair them with the prepared command-range/storage owner after dispatch construction. It must preserve inactive output semantics, actual completion/publication and other processor placements. No such new operand/consumer is implemented here; reconstructing membership from `where`, adding a host `_Repeat`, or claiming zero-domain dispatches are complete command suppression would not close this gap.
