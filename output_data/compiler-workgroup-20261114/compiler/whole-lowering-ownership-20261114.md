## Exact replacement boundaries

The top boundary is the **original compiler's returned pre-terminal result**.
`GraphLowering.codegen` currently constructs the Scheduler, invokes its codegen
and generates the wrapper. MPS `SIMDScheduling.codegen_node_schedule_with_kernel`
(installed `simd.py:3256`) holds the actual node schedule, including reduction
scope sentinels, and produces the finalized indexing/range/KernelArgs/body state.
The subsequent `codegen_kernel`/`define_kernel`/`call_kernel` sites terminalize it.
CPU `KernelGroup.finalize_kernel` (`cpp.py:6120`) retains the actual
`CppKernelProxy`/loop nests; `flush` (`cpp.py:6072`) terminalizes the group. A
Scheduler-node list or one outer-depth integer is insufficient for either body.

The whole returned owner must also include the original wrapper's control,
allocation and AOT interface transformations, all source origins and selected
extern calls. The existing hook has not yet made this the compiler return value.
The driver then supplies its new accesses/workspace/source correspondence to the
ordinary analysis/allocation owners. Terminal emission consumes those results
and native configuration. Distinct first/later programs reuse the numerical
result and original emitter implementation; they do not re-run scheduling,
recover semantics from source text or repeat solved access analysis.

This implies four connected replacement units for root's combined workgroup
order, rather than one issue/one helper iterations:

1. Original entry → complete returned body/control/interface/provenance result →
   Scheduled/native/archive retention, displacing the captured factory side
   channel, flat entry authority and preliminary compiled wrapper.
2. Cited method bodies and typed native calls → that same upstream compiler,
   displacing the remaining Region/Generic numerical compiler and its live
   meta-tensor copy consumers; preserve complete method/precision/RNG/error scope.
3. Original buffer/index/access/allocation results → exact native relation and
   binding projection → ordinary planning, displacing Buffer retyping,
   independent-term approximations and per-name allocation/order reconstruction.
4. Retained numerical body plus produced protocol/page/primitive/configuration
   operands → original target emitter → typed native entry/archive, displacing
   duplicate protocol/source handling and stale/incomplete per-target consumers.
