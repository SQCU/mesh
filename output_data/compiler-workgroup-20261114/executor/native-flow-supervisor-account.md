## File-scope closure and reachability

- All eight Makefile `METAL_IR_SRCS` are accounted: `metal_ir.mm` (views, effects, regions, mappings/Work, placement/dispatch results), `metal_clone.mm` (typed Clone/signatures/owner correspondence), `metal_transform.mm` (current general numerical transform and selected mappings), `metal_lower.mm` (construction, composition, final source/target/native entry), `metal_native.mm` (custom target/method mapping and ABI), `metal_transport.mm` (obligations/protocol/readiness/completion), `metal_neural.mm` (existing MIL target consumer and open precision/control), `metal_archive.mm` (same saved owners).
- Recorder closure is `metal_capture.m`, `metal_program.m`, `metal_capture.h`, `metal_recording.h`, `metal_program.h`, `metal_submission.h` and the generated header that embeds those implementations. `metal_recording.m` is intentionally malformed and absent from `RECORDING_SRCS`; it is not a live second implementation.
- Provider closure is `provider/litert_mesh.cc/.h`, `litert.patch`, `dawn.patch`, original selected LiteRT/MLDrift compiler objects and Tint. Dawn library mode is the existing Raise/Print pipeline, not a second printer. `metal_binary64.wgsl` and generated shader/program headers remain dependencies, including notices; inclusion is not independent implementation.
- Graph/planner/bridge closure is Mesh `rdma/mesh-graph.c/.h`, `mesh-collective.c/.h`, `mesh-dataflow.c/.h`, `mesh-call.c/.h`, `mesh-metal.m/.h` and their existing row/state/layout types. Graph result archives, `mesh_local_load`/`mesh_program_load`, actual row relocation and mapper ownership were inspected. `mesh_view_program` maps retained actual rows; `mesh_view_values` is the older run-only Function mapping used by the compiled `tools/e2b_replay.m` route. Its smaller contract is not equivalent to program-wide page projection and must not be silently substituted.
- Frontend's AST/source trace: `schedule.solved`/`argument_buffers` have no ordinary driver caller; `mesh_view_values` Python calls there and in `rdma/mesh_compile.py` do not establish an active ordinary pipeline. `rdma/mesh_compile.py` is syntactically disabled at7628, `lower_coreml.py` at321. Their old numerical/control/native execution responsibility is a disabled alternative, not observed live support. `mesh_coreml.py/.m` and `mesh_metal4.py/.m` wrappers parse and implement concrete APIs; their visible alternative Python route is that disabled CoreML lowerer. Retain or delete these with the whole affected caller replacement, not by guessing from symbol existence.
- `mesh_code.py` is active source; its old `_fragment` scalar decoder lives in disabled `mesh_compile.py`, while current tensor decomposition is compiler-owned. There is no separate C fragment compiler to audit. Public native/provider tools remain the existing clients; no new client was run for this account.

## Decision and limits

The immediate native assignment is the joined body/configuration/access/Work/transport/emission/archive responsibility (rows1,3,4,7,8), coordinated with original upstream producer ownership. Region/order/lifetime/replay (row5) is a complete second replacement unit. Provider numerical responsibility (row2) is part of the same full AOT scope and requires an explicit whole-source replacement assignment; it is not closed by the Torch path.

The inspected code establishes these responsibility boundaries and the listed repetitions. It is not a claim that every numerical opcode in the provider/ANE or every unrelated rdma service branch has been validated. No new helper/schema, source edit, import, build or workload was performed for this account. Remaining details should be resolved inside these whole replacement units, not by accepting isolated patches or starting another review campaign.
