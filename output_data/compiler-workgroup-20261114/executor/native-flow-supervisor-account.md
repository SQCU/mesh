Lifetime inputs originate only in the original semantic/API/resource owner (including caller ownership); intervals and copies originate in the canonical graph/lifetime/allocation result derived from those inputs. Native preparation, binding and archive borrow those explicit values and owners. A downstream guess based on payload presence, image identity or convenient destruction order is not a lifetime contract. This applies jointly to XNN delegate/runtime resources, context templates, caller tensor storage and MLModel/MLState execution instances.

Index coordination is executor-owned: source writers continue disjointly, report exact coherent hunks, and receive one named staging window. `51988113` accidentally included a pre-staged131 hunk; the source remains preserved and has been independently inspected. Source review and the next matched build cover the whole connected family above. Ordinary WIP checkpoints preserve progress without accepting incomplete numerical/control/precision or performance coverage.

## Decision and limits

The immediate native assignment is the joined body/configuration/access/Work/transport/emission/archive responsibility (rows1,3,4,7,8), coordinated with original upstream producer ownership. Region/order/lifetime/replay (row5) is a complete second replacement unit. Provider numerical responsibility (row2) is part of the same full AOT scope and requires an explicit whole-source replacement assignment; it is not closed by the Torch path.

The inspected code establishes these responsibility boundaries and the listed repetitions. It is not a claim that every numerical opcode in the provider/ANE or every unrelated rdma service branch has been validated. No new helper/schema, source edit, import, build or workload was performed for this account. Remaining details should be resolved inside these whole replacement units, not by accepting isolated patches or starting another review campaign.
